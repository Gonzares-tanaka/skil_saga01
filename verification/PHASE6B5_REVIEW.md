# Phase 6B.5 演出・大型ボス実装報告

Skill Seekers!!~深淵のアムリタ~ / 2026-10-06

アムリタの専用演出と、ロードオブエリシオン専用48×48画像の描画を追加しました。ゲームルールを持つ `rpg/battle.py`・進行を持つ `rpg/finale.py`・チェックポイントを持つ `rpg/final_battle.py` は着手時のファイルと同一です。

## 1. アムリタ演出の流れ

実際のITEM行動でバリア有効から無効へ変わった瞬間を、UI側で検出します。使用メッセージ、フラッシュ、ボスの上から降り注ぐ光、着弾時の点滅と小さな振動、障壁の破片、障壁消失を表示し、通常の行動解決へ戻ります。予約時や通常のPOTION使用では始まりません。確認後の表示調整で、上部の常時ボス名を削除しました。対象選択時・メッセージ内の名前は維持しています。

## 2. 演出時間

[rpg/final_presentation.py](../rpg/final_presentation.py) の `AMRITA_EFFECT_FRAMES=45`、30FPSで約1.5秒です。`AMRITA_EFFECT_MAX_SECONDS=2.0` の実時間期限も持ち、画面が非表示だった場合は復帰後最初の更新で期限を確認します。音声の再生状態は参照しません。

## 3. 使用した視覚効果

| フレーム | 演出 |
|---|---|
| 0～3 | 使用メッセージとボス周辺の障壁 |
| 4～5、10～11 | 最も明るい色3による全画面フラッシュ |
| 12～23 | ボスの真上から3本の直線と十字型の光が降り注ぐ |
| 24～31 | ボス・障壁のON/OFF点滅、左右±1～2pxの振動 |
| 32～37 | 障壁の点が外へ飛び、暗くなって消える |
| 38～44 | 障壁なしのボス、破壊メッセージ |

全て既存の色0～3とPyxelの描画だけで成立します。大量のパーティクルや半透明処理は使用しません。描画の色変換は `finally` で戻し、以降の画面へ残しません。

## 4. バリア表現の実装方法

`FinalPresentation.barrier_points()` がスプライトの中心・幅・高さから16個の光点を楕円状に配置します。通常時は点の明暗が周期的に変わり、破壊時は点滅・外向き移動・消失へ移ります。点・破片は左側の戦闘領域内に制限し、名前・味方・メッセージに重ねません。

## 5. バリアON/OFFの描画方法

通常戦闘画面では `elysion_barrier_active=True` のときだけ光点を描きます。Falseなら描きません。破壊演出中だけ、既に解除済みの障壁の残像を短時間表示します。この残像はゲーム効果を持たず、38フレーム目以降は消えます。

## 6. アムリタ演出Stateの有無

`amrita_effect` を追加しました。`resolve → amrita_effect → resolve` と戻り、行動キュー・ラウンド・結果を演出中に更新しません。モデルの戦闘状態やチェックポイントの項目は変更していません。

## 7. 入力ロック方法

`App.update()` と `DungeonApp.update()` の先頭で演出状態を処理し、通常のA/B・十字キー・情報・ヘルプ・DEBUG操作へ入らないようにしました。終了後は既存の `battle_input_blocked` で全操作ボタンを離したフレームを待ち、新規入力から再開します。終了時刻までの入力を予約しません。Qによる終了は可能です。

## 8. 演出失敗時の進行保証

従来のITEM処理がバリアをFalseにしてから専用演出を開始します。演出時間・描画・SEの成功をバリア解除の必須条件にしません。

45回の更新または実時間2秒の期限で終了します。演出開始・更新・描画が例外になった場合も演出状態を解除し、通常の戦闘解決へ戻します。描画を一度も呼ばない場合、背景復帰で実時間期限を超えた場合、描画関数を故意に失敗させた場合を検証しました。既存の音声例外処理・ファンファーレの最大待機時間を保持しています。

## 9. ロードオブエリシオンのSpriteサイズ

**48×48**です。現画面は160×120、上部帯はy=0～10、味方情報はx=97以降、メッセージとコマンドはy=80以降です。48×48なら `(24,24)` に配置し、光点・小さな振動まで含めてこの間に収まります。64×64は上下UIと演出の余白を確保できないため採用していません。通常敵と既存ボスの16×16描画は維持しています。

## 10. .pyxres内のSprite領域

`game.pyxres`、**Image Bank 0、x=144～191 / y=64～111**です。着手時に全画素が色0だった領域を確認しました。既存の通常敵・大きく手編集されたボス・施設・ダンジョンタイルを上書きしていません。新しい仮画像は王冠・鎧・外套・剣の輪郭を48×48の解像度で描き、16×16画像の拡大はしていません。

`tools/add_elysion_sprite.py --write` は明示的な一度限りの生成用です。領域内に既存の絵があれば書き込まず終了します。起動・Editor起動・Webビルドからは呼びません。生成前の原本はGit対象外の `verification/backups/phase6b5/` に保存しました。

## 11. Pyxel Editorで編集する場所

`edit.cmd`で `game.pyxres` を開き、Image Bank 0の `(144,64)` から48×48を編集してください。色0が透明です。描き直した画像をWeb版へ反映するには、従来どおり `tools/build_web.cmd` で再ビルドし、`game.pyxres` と `dist/game.html` をPushします。

画像領域の指定は [data/final_battle.json](../data/final_battle.json) の `boss_sprite` にまとめました。

```json
"boss_sprite": {"bank": 0, "u": 144, "v": 64, "width": 48, "height": 48, "colkey": 0}
```

48×48以内の有効な領域だけを受け付けます。通常の敵データにある小さい `sprite` は変更せず、最終ボス専用の描画だけこの設定を参照します。

## 12. 大型Sprite描画処理

[rpg/app.py](../rpg/app.py) の `draw_lord_of_elysion()` から、分離した `FinalPresentation.draw_boss()` を呼びます。専用描画には拡大率を渡さず、.pyxresの画素をそのまま描きます。最終戦の敵IDが `lord_of_elysion` の場合だけ切り替え、通常の敵描画には16×16のまま渡します。ターゲットカーソルも専用の幅・高さから位置を計算しています。

## 13. UI干渉テスト結果

実Pyxelで開始時・ターゲット選択・45フレームの演出・解除後・再挑戦を描画しました。ボス・光点・破片は左側戦闘領域に収まり、ボス名、4人の名前・HP、コマンド、ターゲット名、メッセージを隠しません。フラッシュ中の4フレームだけは要求どおり画面全体を明るくします。

常時ボス名を削除した表示調整後の専用試験で1,139回、調整前の最終戦からENDINGまでの試験で25,824回の文字描画が160×120内に収まることを検査しました。開始・上からの光・破片・消失後・ターゲット・再挑戦のスクリーンショットを目視確認しました。

## 14. 全滅→再挑戦時のバリア復元結果

実アムリタ使用・解除後に全滅し、既存のチェックポイントから再挑戦しました。`has_amrita=True`、`elysion_barrier_active=True` と障壁の描画が復活しました。演出オブジェクトを戦闘開始ごとに破棄して作り直すため、開始時はフレーム0・非演出状態です。4回連続全滅でHP・技・Uses・ITEM等が復元され、5回目には撃破からENDINGへ進む既存試験もPASSです。

## 16. 既存ゲームロジックを変更していないこと

着手時ハッシュと比較し、`rpg/battle.py`、`rpg/final_battle.py`、`rpg/finale.py`、全敵データ、成長・スキル・ITEM・ダンジョン・石碑・拠点・QUEST・INTRO等のJSONは同一です。アムリタ使用条件・1行動消費・効果・力消費の時期、チェックポイント保存対象・復元、撃破・ENDINGの進行は維持しています。

データの変更は `data/final_battle.json` の描画メタデータ追加と、障壁破壊メッセージの変更だけです。ゲーム資産はImage Bank 0の新規48×48領域だけを追加しました。リソースの全Tilemap・他Image Bank・音声は構造を比較して同一、area2/3資産と全パレットはバイト単位で同一です。今回B15の範囲設定も変更していません。

## 17. 既知の問題

- 画像は表示確認用の仮ドット絵です。完成版はPyxel Editorで差し替えてください。
- 専用SEは未追加です。既存のITEM/技の音を従来どおり鳴らし、演出の終了は待ちません。
- 実ブラウザ・スマートフォンでの描画と画面ロック復帰の現物確認は残っています。
- 低FPS端末ではフレーム演出の見え方が短くなる場合があります。進行のため実時間2秒で必ず解除します。
- セッション内チェックポイントのみで正式セーブは未実装、ボスの能力とENDINGはPhase 6Bの仮設定を維持しています。
