## 6. Pyxel Editorでの編集方法

`edit.cmd`を実行→`game.pyxres`のImage Bank 2→左上(80,0)から16×16を編集して保存してください。通常のゲーム起動・ビルドは仮画像を再生成しません。作成ツールは空き領域だけを対象とし、再実行して既に画像がある場合は上書きを拒否します。

Webは`tools/build_web.cmd`で再ビルドして`dist/`を公開、GKDはゲームデータを含む更新ZIPをコピーする必要があります。

## 8. エレベータ解放条件

| B11 | `9 in defeated_bosses`（B10撃破） |

新しい独立した解放フラグは作らず、旧セーブの撃破状態からも判定します。未解放は非表示。全未解放なら「まだ行き先がありません」と「もどる」だけです。移動関数側でも解放を再検証します。

## 9. B6・B11・B15の到着座標

すべて0始まりのマップ座標です。

| 行き先 | 到着 | BGM |
|---|---|---|
| B6 | (3,3)、既存上り階段 | AREA2 |
| B11 | (3,3)、既存上り階段 | AREA3 |
| B15 | (4,28)、入口近くの通常床 | AREA3 |

B6/B11は既存Tilemapの入口から取得します。B15は入口から到達可能な通常床2×2を距離順に選び、全QUEST候補と重なる場所を除外します。到着点の検証に失敗した場合は探索の初期化前に拒否します。到着処理から`move()`や`interact()`を呼ばず、敵の抽選・強制イベントを発生させません。既存`safe_steps=2`は変更なし。入力を一度離してから新しい入力を受け付けます。

## 10. B15双方向エレベータの仕様

デーモン撃破後だけB15の(4,28)を左上とする2×2マスに同じ16×16アイコンを重ね描画します。上に乗ると案内し、A→確認「はい」で拠点へ戻ります。帰還は自動ではありません。デーモン撃破前とB6/B11には帰りのエレベータはありません。地形・Tilemapは変更していません。

## 11. ストーリーとの整合性

エレベータ移動は既存の新しい探索開始処理を利用します。宝箱開封・スイッチ・泉は通常再出発と同じ扱いで、撃破・アムリタ・クエストは保持します。守護者/デーモンの撃破フラグを戻しません。B15帰還も既存の安全帰還と献上確認へ進むため、「後で」→再訪→帰還→再確認を維持します。

アムリタはKEY ITEMのままです。入手、献上、ロードオブエリシオン、Final Retry、ENDING、守護者3連戦は既存回帰テストで検査しています。実ブラウザの新規テストではボスの撃破状態をテスト用に設定しており、通常プレイで全ボスを倒す通し実機確認とは区別しています。

## 12. 帰還の羽根の内部ID・表示名

内部ID **`return_feather`**、表示名 **帰還の羽根**、初期所持0、上限9。探索ITEM専用で、戦闘ITEM候補には出ません。戦闘ロジックもこのIDを拒否します。通常の対象者用アイテム処理へ直接渡した場合も使用不可です。

## 13. SHOP販売価格と決定理由

**3 TRZ**。Lv2の最小報酬4 TRZを下回り、1件達成後に必ず1～3 TRZが残る設定です。POTIONより高く、既存COMMONのRETURN再習得3 TRZと同額で、技枠を空ける代わりに使うたび費用がかかります。価格の編集箇所は`data/items.json`の`items.return_feather.price`です。

## 14. 既存価格・報酬との比較

| 対象 | TRZ |
|---|---|
| POTION / REMEDY / PHOENIX ASH | 1 / 2 / 4 |
| 帰還の羽根 | 3 |
| Lv1 探索 / 調査 / 討伐 | 2 / 3 / 4 |
| Lv2 探索 / 調査 / 討伐 | 4 / 5 / 6 |
| Lv3 探索 / 調査 / 討伐 | 6 / 7 / 8 |
| TRAINING BASIC / COMMON / RETURN / RARE補助 | 1 / 2 / 3 / 4 |

既存宝箱テーブルのTRZのみの期待値は通常1箱1.09、レア1箱2.70です。実マップの通常箱/レア箱はAREA1が5/1、AREA2が11/4、AREA3が11/5。全箱を開けた場合のTRZ期待値はそれぞれ8.15 / 22.79 / 25.49です。これは監査上の期待値で、確定入手量ではありません。報酬テーブルや配置は変更していません。`alpha_gameplay02_audit.json`に記録しています。

## 15. RETURNとの帰還処理共通化

`DungeonApp.safe_return(lines)`→既存`enter_camp(returned=True)`へ集約しました。徒歩・RETURN・帰還の羽根・B15エレベータが同じ入口を呼びます。RETURNの`Session.field_return()`による技消費・MASTERED判定には変更がありません。

羽根は確認後、安定した探索状態・所持数を再検証し、帰還成功後に1個減算します。取り消し、未所持、連戦/イベント/戦闘中、帰還失敗では減算しません。未確定TRZの確定、HP回復、Uses持越し、QUESTのお礼と報酬、献上確認は既存処理のままです。

## 16. 新アイテムの保存方法

既存の`items`辞書に羽根の個数を含めます。通常SAVE、ファイル/ブラウザのLOAD、中断、最終戦の所持品チェックポイントはいずれも既存辞書の保存対象です。通常・中断それぞれで個数の往復一致を検査しました。
