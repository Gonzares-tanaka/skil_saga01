# α版 Phase 6B 実装・検証報告

対象：Skill Seekers!!~深淵のアムリタ~ / 2026-10-05

アムリタ取得後の献上確認、最終イベント、ロードオブエリシオン戦、特殊バリア、セッション内チェックポイント、再挑戦、仮ENDINGを実装しました。最終戦の再挑戦は最初の戦闘開始状態を復元し、敗北でUsesやITEMが減り続ける状態を防ぎます。

## 1. 拠点での献上確認イベント実装場所

[rpg/dungeon_app.py](../rpg/dungeon_app.py) の `enter_camp()` で外部からの帰還を検出し、`show_amrita_offer()` で `amrita_offer` 画面を開きます。RETURNや階段での帰還は既存の帰還結果画面を確認した後、通常HUBの前に献上確認へ進みます。全滅帰還でも所持条件を満たす場合は確認します。

## 2. 「はい / 後で」の状態管理

`update_final_event()` が選択を処理します。「はい」は `FinaleProgress.start_final_event()` で `final_event_started=True` にし、`final_story` へ移ります。`has_amrita` はTrueのままです。「後で」またはBは `camp` へ戻り、所持・進行フラグを変更しません。施設5つの操作をそのまま利用できます。

状態は `amrita_offer → final_story → 戦闘 → final_retry / ending` として明示しています。NEW GAMEで関連フラグとチェックポイントを初期化します。

## 3. 確認画面の再表示条件

[rpg/finale.py](../rpg/finale.py) の `can_offer_amrita` は `has_amrita and not final_event_started` を判定します。通常の外部帰還を表す `returned / defeated` と組み合わせ、施設間の移動では確認を開きません。「後で」の後にダンジョンへ出て再帰還した場合は再表示します。GUILD・TRAINING・PUB・SHOPからの戻りでは再表示しないことを確認しました。

## 4. 最終イベント文章の編集場所

[data/final_battle.json](../data/final_battle.json) に一括しています。

| 項目 | 用途 |
|---|---|
| `offer_question` | 献上確認 |
| `story_pages` | 王との対立から最終戦までの短い3ページ |
| `battle_start` | 戦闘開始メッセージ |
| `barrier_hint` | 初回無効化時の障壁・アムリタのヒント |
| `amrita_release / amrita_unavailable` | アムリタ使用結果 |
| `retry_question / defeat` | 再挑戦確認・敗北結果 |
| `victory / ending_lines` | 撃破後・仮ENDING |

UTF-8のJSONを編集します。ストーリー・ENDINGは幅に合わせて折り返して8行単位、確認文は5行単位で自動分割し、長い編集文章でも選択肢と重ならないようにしています。空行を保持します。

## 6. `elysion_barrier_active` の管理方法

[rpg/battle.py](../rpg/battle.py) の `Battle` に戦闘ごとのフラグを持たせました。ボスIDが `lord_of_elysion` の最終戦だけ、開始時にTrueになります。通常戦闘には適用しません。

共通の `_damage()` で、バリア有効時にロードオブエリシオンへの全ダメージを0にします。物理・魔法・LEGEND・DRAIN・COUNTERを確認しました。初回だけヒントを戦闘ログへ追加し、次の攻撃で繰り返しません。バリアに弾かれた技でも通常どおりUsesを消費します。

## 7. アムリタ使用処理

[rpg/app.py](../rpg/app.py) の `battle_items()` が最終戦のバリア有効時だけ `AMRITA` をITEM末尾に表示します。通常戦闘では非表示で、直接不正な行動を渡しても拒否します。通常ITEMの個数制限・売買・消費処理に入れません。

`Battle.begin_round()` と `_party_action()` で、1人の1回の行動として処理します。同じキャラクターが同じラウンドにSKILLも実行することや、複数人で同時にアムリタを予約することは拒否します。使用時はバリアをFalseにし、解除文を表示します。`has_amrita` はTrueのまま、UsesやITEM個数は消費しません。撃破確定時に初めて `lord_of_elysion_defeated=True`、`amrita_power_spent=True`、`has_amrita=False` にして仮ENDINGへ進みます。

## 8. FINAL BATTLE CHECKPOINTの保存対象

[rpg/final_battle.py](../rpg/final_battle.py) の `FinalBattleCheckpoint` が最終戦に入る直前に一度だけ保存します。

| 対象 | 保存する状態 |
|---|---|
| パーティ | HP、全能力値、習得技、残りUses、成長履歴、個人の技関連状態 |
| 技の共有状態 | 収集済み技、MASTERED、保留中の再習得等 |
| 資源 | ITEM所持数、BANKEDと未確定TREASURE |
| セッション | 戦闘回数・勝敗数、DEBUG等の関連フラグ |
| ダンジョン | 階・位置・歩数、開封箱、スイッチ、報酬、撃破済みボス |
| 探索 | QUEST対象・調査・達成状態、泉利用状態 |
| 最終進行 | 守護者、デーモン、アムリタ、最終イベント・撃破・力消費、既読石碑 |
| 乱数 | RNGの状態 |

ファイル保存はせず、現在のセッションだけで管理します。ロード済みルール、Tilemap、画像、音声は保存・再生成しません。保存項目を明示し、将来のセーブ実装で対応付けやすくしています。

## 9. 全滅時の復元方法

最終戦の結果は `finish_results()` で通常全滅分岐より先に扱います。DEFEATだけでなく、制限ラウンド到達によるDRAWも `final_retry` へ進みます。通常の宝ロスト・拠点全滅回復は適用しません。

「はい」は最初のチェックポイントから毎回新しいコピーを復元し、パーティの共有MASTERED、ダンジョンのITEM・TREASURE・RNG、探索の参照もつなぎ直します。その後、新しい最終戦を作り、バリアTrue、HP満タンのボス、空の行動予約・メッセージキューから再開します。音声待ちやUIの一時状態を解除し、ボタンを離してから新規操作を受け付けます。敗北後の状態でチェックポイントを上書きしません。

「いいえ」またはBはタイトルへ戻ります。画面にその結果を明記しました。正式なセーブがないため、続きからの再開はできません。

## 10. アムリタ使用後全滅テスト結果

実際のITEM選択でアムリタを使用してバリアを解除した後、全員のHPが0になる敗北を発生させました。結果画面から再挑戦し、`has_amrita=True`、`elysion_barrier_active=True`、開始前HP・Uses・ITEM・TREASURE・フラグの復元を確認しました。

画面操作試験では音声APIの `play / playm / stop` をすべて例外にし、音声が使えない状態でこの手順を完了しました。現物のスマートフォン画面ロックを再現した試験ではありません。

## 11. 複数回敗北時の詰み防止確認結果

4回連続で、アムリタ解除、POTION計7回の実使用、全滅、再挑戦を繰り返しました。最初の試行ではMETEORを実使用してUsesを使い切り、技の消失・MASTEREDまで進めています。4回とも元の技・Uses・道具・宝・進行が戻り、同じチェックポイントから再開できました。5回目の挑戦は撃破し、ENDINGと力消費フラグを確認しました。

追加の単体テストでも、能力値・習得技・履歴・共有参照・複数フラグを変更してから4回復元し、原記録が変更されていないことを比較しています。判定用に準備したパーティを用いた試験で、自然な育成後のボス難易度はまだ調整対象です。

## 13. B1～B15の維持と必要だった設定修正

現在のリソースを用いたPhase 6A回帰試験は、B10撃破後からB11～B15、石碑・守護者3連戦・泉・デーモン・アムリタ取得・RETURN帰還まで通過しました。D-Pad移動298回、戦闘19回、画面内テキスト描画16,527回を確認しています。帰還時の新しい献上確認では「後で」を選び、通常HUBに戻ることを確認しました。過去の初期生成用幾何レポートは手編集後の座標の保証には使用していません。

## 15. 既知の問題・今後の確認

- ボス能力・画像は仮設定です。通常育成での難易度は人間のプレイテストで調整が必要です。
- ENDINGは接続確認用の短文です。完成版文章・画像・演出は未制作です。
- チェックポイントはセッション内のみです。ゲームを閉じる、または再挑戦を断ってタイトルからNEW GAMEを選ぶと続きは復元できません。
- 実ブラウザ・スマートフォンの動作、とくに画面ロックからの復帰は実機確認が残っています。
- 今回の試験・セルフレビューでは、最終戦の資源消失、永久音声待ち、画面外の文字描画は検出していません。
