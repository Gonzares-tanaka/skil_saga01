## 2. Q / F9 / キーボードA

`rpg/runtime.py` の `development_enabled()` は、明示的にDEBUG起動したPCソース版のみ許可。通常の `run.cmd` 起動では無効。開発起動は `python main.py --debug`。

- Q即終了とF9によるDEBUG切替は `debug_allowed` が必要。
- キーボードAの自動戦闘は、さらに現在DEBUGがONである場合だけ有効。
- Z / ゲームパッドA / タッチAの決定操作は維持。
- Web・GKD通常版・GKD診断版のコピーに限り `DEVELOPMENT_BUILD=False` を埋め込む。Webは `emscripten` の場合も拒否。
- 旧中断にDEBUGが含まれていても、通常版への復帰時にDEBUGだけを解除。ゲームのHP・Uses・進捗を初期化しない。
- GKD診断ログ・設定・ウォッチドッグ、SELECT単独約1秒長押しによる終了は維持。

## 3. 画面重複

## 4. カーソル記憶

以前は `Battle._party_action()` で実際に技を使うまで記憶が更新されなかった。`App.commit()` で対象まで確定した技をキャラごとに記憶するため、行動前に戦闘不能になっても選択が残る。技一覧を眺めるだけ、対象確定前のBキャンセルは記憶を書き換えない。

`Character.forget()` は消えた技より後ろの記憶インデックスを調整。記憶したIDが残っていればそれを優先し、消えた場合はその位置に近い有効な技を選ぶ。戦闘間も既存フィールドを使い、セーブ形式を増やしていない。

## 9. カイINTの変更前後

基礎INT上昇率：ロウ12%、カイ12%、ミオ55%、セン12%。従来の技使用補正は `min(35%, growth_points[INT]×4% + カテゴリ補正)`。魔法・回復カテゴリは1使用あたりINT+5ポイント、各カテゴリ最大3使用。

追加分は **カイのみ、魔法＋回復使用数の合計×3ポイント、合計最大3使用・9ポイント**。従来35%上限の外側に加算する。上限の内側だと魔法多用時に既に35%へ達しており、改善効果が出ないため。最後の成長判定は従来どおり100%で頭打ち。

設定場所：`data/settings.json:character_int_growth.kai` の `categories / per_use / max_uses`。処理：`rpg/growth.py:growth_bonus()`。INT以外・他の3人・初期能力を変更していない。

ファイア3回使用では、カイ47%→56%、ミオ90%→90%。魔法・回復を使わない速攻中心の条件ではカイ12%→12%。

## 20. 実機確認が必要な事項

iOS SafariとGKD Pixel 2実機で、長押しや復帰後の操作感、実音声、日本語の読みやすさを確認する必要がある。ブラウザのスマホ幅タッチ検証は実iPhoneでの画面ロック試験の代わりではない。今回、音声待ち・復帰ガードのロジックは変更していない。

カイの強化は統制条件の成長シミュレーションで検証したもの。自然な閃き・戦闘回数・技入替を含めた中盤～終盤の実用性、クエスト選択率の再測定は外部テストで確認する。報酬効率を全パーティ・全帰還手段で均等化したと主張しない。
