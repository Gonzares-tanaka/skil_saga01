## Phase 7A / 7B / 7C：SAVE / LOAD

PC Python・PCブラウザ・スマートフォンブラウザで、**拠点 → GUILD → SAVE → はい**から保存できます。スロットは1つです。次回起動後、タイトルの**つづきから**を選ぶと、導入を飛ばして通常の拠点TOPから再開します。Aで決定、Bで取り消します。保存完了・失敗のメッセージからはA/BでGUILDへ戻れます。スマートフォンも十字キー・A/Bだけで操作できます。NEW GAMEだけでは既存SAVEを上書きせず、次にSAVEした時点で上書きします。

| 環境 | Backend / 保存先 | Phase 7C確認状況 |
|---|---|---|
| PC Python | FileSaveBackend / 実行ディレクトリ基準の`save/save.json`。`run.cmd`ではプロジェクト内 | Python 3.14.7・Pyxel 2.9.9。別プロセスで終了・再起動・再保存を確認 |
| PCブラウザ | BrowserSaveBackend / ゲームURLのオリジンに属するlocalStorage | 実Edge・実Pyodideで確認 |
| スマートフォンブラウザ | BrowserSaveBackend / 同じくlocalStorage。PC・他ブラウザとは自動同期されない | 対象実機はiOS Safari。EdgeのPixel 7タッチ模擬環境のみ確認済みで、iOS実機は未確認 |
| GKD Pixel 2 Python | FileSaveBackend / 書き込み可能なディレクトリ内のJSON | plumOS / Python 3.11.7 / Pyxel 2.9.9 / aarch64を更新後の実機ログで確認。ゲーム起動・SAVE動作をユーザーの実機確認で確認済み。終了操作の追加とLOADは実機確認待ち |

ブラウザではSAVE後にページを再読み込み・タブを閉じても、同じURL・同じブラウザからCONTINUEで再開できます。**サイトデータを削除すると保存も消えます。** プライベートモードやブラウザ設定によっては保存を保持できない場合があります。保存できない場合は失敗メッセージを表示し、ゲームへ戻れます。未保存の進行は終了すると失われます。Web版はHTTP(S)で開いてください。

能力値・技構成と残りUses・DISCOVERED/MASTERED・道具・確定TRZ・累計戦闘回数・QUEST記録と受注中の依頼・ボス撃破とストーリー進行・初回拠点説明済みフラグを保存します。LOAD時に初期3 TRZを追加しません。未確定TRZは保存せず、LOAD後は0です。受注中QUESTの依頼ID・対象階・進捗は保持し、シンボル位置だけ安全な候補へ再配置します。LOAD直後にはアムリタ献上確認を出さず、次に外から拠点へ帰還したときに既存条件で表示します。

ダンジョン内・戦闘中・イベント中・最終戦チェックポイント中は保存できません。探索位置、一時効果、音声待ち、FINAL BATTLE CHECKPOINTは保存しません。PCファイルはUTF-8のJSONで、一時ファイルを書き終えてから置換します。ブラウザも同じSaveDataをJSON文字列にして保存します。破損・必要項目不足・未対応バージョンは読み込み失敗として扱い、元データを自動修復・削除・上書きしません。プレイヤーの`save/`はGit管理・Web配布の対象外です。

実装は[rpg/save.py](rpg/save.py)に集約しています。共通データ変換は`make_save_data()` / `apply_save_data()`、版移行の入口は`migrate_save_data()`です。`default_backend()`の1箇所で、Pyodideの`emscripten`は`BrowserSaveBackend`、PC Pythonは`FileSaveBackend`を選びます。ファイル保存先は`FileSaveBackend(path)`、ブラウザのキーは`BROWSER_SAVE_KEY = 'skill_seekers_save_v1'`で変更できます。キー名とデータ内の`save_version = 1`は別に管理し、URLのクエリ文字列はキーに含めません。`SaveManager`へ`read()` / `write(data)`と`available`を持つバックエンドを渡すことで保存媒体を交換できます。将来のデータ変更では、IDの維持と`save_version`の移行処理が必要です。

ブラウザでは既存Pyodideの`js`モジュールからlocalStorageへ直接接続します。保存と音声処理は独立しています。IndexedDB、クラウド同期、EXPORT / IMPORT、GKD専用処理は追加していません。確認内容と制限は[Phase 7C統合確認報告](verification/PHASE7C_REVIEW.md)、ブラウザ実装は[Phase 7B報告](verification/PHASE7B_REVIEW.md)、共通SaveDataの設計は[Phase 7A報告](verification/PHASE7A_REVIEW.md)を参照してください。

PC / GKDのファイル保存先は、[rpg/save.py](rpg/save.py)の`DEFAULT_SAVE_PATH = Path('save') / 'save.json'`で一箇所に設定できます。起動前に書き込み可能な場所を指定してください。既存の`DungeonApp(..., save_backend=FileSaveBackend(path))`による指定も可能です。ディレクトリはSAVE時に作成し、権限不足はSAVE失敗として扱います。GKDではランチャーの作業ディレクトリ・SDカードのマウント先・書き込み権限を実機で確認する必要があります。Windowsのドライブ名やユーザー名は保存コードに固定していません。

現在固定している[Pyxel 2.9.9](https://pypi.org/project/pyxel/2.9.9/)はPython 3.11以上を要求します。2026-10-10のユーザー提供ログで、GKDのPython 3.11.7 / Pyxel 2.9.9 / aarch64を確認しました。旧Pyxel 2.3.6とのバージョン差は更新によって解消しています。これはパッケージ版の確認であり、ゲーム起動・表示・入力・音声・SAVE / LOADの実機確認はまだ必要です。plumOSの公式更新方法はUSB Wi-Fi接続後のTools → `pyxel_update`です。GKD向けにゲーム本体・依存固定版・リソース形式を変更していません。

**plumOSでのバージョン確認：** [公式資料](https://github.com/game-de-it/plumOS-pixel2#pyxelについて)はPythonの場所を`/storage/pyxel_Python/bin/python3`と案内していますが、正確なPython・Pyxelの同梱版は記載していません。Pyxelは更新可能なので実機の値を確認します。[tools/check_gkd_versions.sh](tools/check_gkd_versions.sh)をGKDの`roms/ports/`へコピーし、Portsから実行すると、`gkd_versions.txt`にバージョンが出ます。パッケージの更新・ゲーム起動・SAVE変更は行いません。実行したPython環境のメタデータを確認するだけなので、ゲームが別のランチャー環境を使う場合はその設定も照合してください。

診断スクリプトのrevision 2は、まず`/storage/roms/ports/gkd_versions.txt`への出力を試み、Python起動前に`CHECK START`を書きます。Pythonが失敗してもエラーと終了コードを記録します。Portsに書けない場合はスクリプトのフォルダ、作業ディレクトリ、最後に`/tmp/gkd_versions.txt`へ出力します。ログ先頭の`Report path`で実際の場所を確認できます。PC側の修正はGKDへ自動反映されないので、GKDの`.sh`を上書きコピーしてください。ファイルはLF・BOMなしを維持します。`.txt`はPortsのゲーム一覧ではなく、PC／ファイルマネージャーで確認します。

Phase 7Cでは218件の自動テスト、PCでの3プロセス保存・復元、実Edgeでの再読み込み・ブラウザ再起動を確認しました。実AudioContextを停止し、`resume()`を失敗させ、ページをfreeze/復帰させても戦闘・勝利・探索復帰・SAVE / LOADは進行しました。ヘッドレスEdgeのタブ切替では実際の`document.hidden`遷移を再現できなかったため、非表示イベントの処理は合成イベントで別途確認しています。スマートフォンの画面ロック実機試験とGKD実機試験は残っています。SaveDataはversion 1のままで、ゲーム本体・マップ・素材・配布用`dist`の変更はありません。

## Phase 6D：QUEST 3種と通貨TRZ

通貨の表示名は **TRZ** です。内部の`treasure / banked / unbanked`は維持し、未確定TRZは入口・RETURNによる安全帰還で確定、全滅時には未確定分だけ失います。

**NEW GAMEは確定TRZ 3・未確定TRZ 0から開始**します。初期資金は`rpg/opening.py`の`NEW_GAME_BANKED_TRZ`を新規開始時だけ設定し、帰還時などには加算しません。PC版LOADでは保存された確定TRZを復元し、未確定TRZは0にします。初期3 TRZは加算しません。

PUB → QUEST → **Lv1・Lv2・Lv3を選択 → 探索・調査・討伐を選択 → 依頼文を読む →「受注する／受注しない」を選択**します。各画面で上下キー／D-PADで選択し、Aで決定します。確認画面のBも「受注しない」と同じ扱いで種別選択へ戻ります。未解放Lvには必要なボス撃破条件を表示し、受注できません。対象階・地点は選んだLvの範囲内からランダムに決まります。

同時受注は常に1件です。受注中は現在の種別・Lv・対象階・進捗・報酬を表示し、新規受注はできません。目的達成後に入口またはRETURNで安全帰還すると、依頼人のお礼 → QUEST COMPLETE・TRZ報酬 → 拠点と進みます。お礼・報酬はAで進めます。全滅ではお礼・報酬・達成記録は発生しません。同じ種別・Lvも再受注可能です。

QUESTには種別・Lvごとの短い依頼文・依頼人・固有のお礼があります。通常候補は各3件、計27件です。文章は[data/quest_flavors.json](data/quest_flavors.json)の`texts → explore / investigate / hunt → "1" / "2" / "3"`で編集できます。各候補は`id / requester / lines / complete_lines`のデータです。

```json
{
  "id": "investigate_l2_01",
  "requester": "歴史研究者",
  "lines": ["この地下には古代の水脈が", "残っているらしい。", "各所の痕跡を調べてくれ。"],
  "complete_lines": ["やはり古代の水脈があったか！", "この痕跡なら論文が書けるぞ。", "調査してくれてありがとう。"]
}
```

確認画面で候補を選び、依頼人・文章・対象階・必要数・報酬を表示します。「受注する」までは`pending_quest`として一時保持し、受注・進捗・TRZには影響しません。確定すると表示中の内容をそのまま`active_quest`へ移し、文章は`flavor_id`だけを保持します。辞退してもゲーム本体の乱数と前回受注したIDは変えません。

受注後は画面の開き直しや階層移動・全滅で再抽選しません。通常27件の`id`は将来のセーブ互換性のため固定し、変更・削除・置換しないでください。文章・依頼人・お礼文は編集できます。古い受注にIDがない場合や見つからない場合は、同ファイルの`fallbacks`にある種別・Lv別の汎用依頼文とお礼文を表示します。選択した種別・Lvの中に未達成の通常IDがあれば、その候補から優先抽選します。全3件達成後は通常抽選へ戻り、候補が複数ある限り前回受注IDとの連続を避けます。文章用の乱数は対象階・戦闘・成長用の乱数と独立しています。

**GUILD → QUEST RECORD**で、探索・調査・討伐の累計CLEAR、固有達成数（各9件）、整数の達成率、TOTAL（27件）を確認できます。BでGUILDへ戻ります。同じIDの再クリアもCLEARには加算し、固有達成数には加算しません。27/27では100%とCOMPLETE!を表示します。追加報酬はありません。汎用fallback9件はCLEARのみ加算でき、固有達成数・分母には含めません。

記録は`Exploration.quest_clear_counts`（種別別dict）と`completed_quest_ids`（重複しないIDのlist）に保持します。NEW GAMEでゼロから初期化します。正式完了は`rpg/exploration.py`の`finalize_quest_completion()`に集約し、お礼の最後のAで報酬・記録を一度だけ更新して受注を解除します。固定対象は`rpg/quests.py`の`QUEST_COMPLETION_IDS`です。GUILDのSAVEで上記dict/listを保存し、CONTINUEで復元できます。未保存の進行は終了すると失われます。お礼文は2～3行を基本とし、長文は自動折り返し・7行ごとのAページ送りに対応します。実装と確認範囲は[QUEST仕上げ報告](verification/QUEST_FINISH_REVIEW.md)を参照してください。

初期文章は1画面に収まります。長く編集すると、実際の日本語フォント幅で自動折り返しし、3行ずつAで読み進められます。受注前は最後のページで受注するかを選び、途中のAでは受注しません。受注後の確認画面では最後から最初へ読み返せます。依頼人・対象階・進捗・報酬・安全帰還条件は固定表示です。`rpg/quests.py`の`QUEST_FLAVOR_MAX_CHARS`（4px単位、36＝144px）・`QUEST_FLAVOR_LINE_HEIGHT`・`QUEST_FLAVOR_LINES_PER_PAGE`が文章枠の設定です。依頼人名が長すぎる場合は末尾を`~`で省略します。検証の詳細は[QUEST依頼人・フレーバー報告](verification/QUEST_FLAVOR_REVIEW.md)を参照してください。

| 種別 | 目的 | Lv1 / Lv2 / Lv3の報酬 |
|---|---|---|
| 探索 | 人影シンボル1地点へ接触、またはAで調べる | 2 / 4 / 6 TRZ |
| 調査 | 虫眼鏡シンボルをLv1は2地点、Lv2・Lv3は3地点調べる。重複カウントなし | 3 / 5 / 7 TRZ |
| 討伐 | 魔物の顔シンボルへ接触し、既存敵を使った1体の追加戦闘に勝つ | 4 / 6 / 8 TRZ |

**Lv1はB1～B5、Lv2はB6～B10（B5ボス撃破後）、Lv3はB11～B15（B10ボス撃破後）**です。依頼画面に対象階を明示します。全滅すると受注は残り、未報告の進捗を失って同じ対象へ再挑戦します。討伐のRUN・DRAWでは達成せず、対象が残ります。討伐でも通常の成長・閃き・Uses消費を使い、QUESTのTRZ報酬は帰還まで渡しません。

配置は既存のTilemapの`TILE_QUEST`候補と、`data/dungeon.json`の各階の`quest_spawn_points`から選び、マップ自体を変更しません。追加座標は普通の床であり、ボス・守護者・警告イベントを越えずに到達できる場合だけ有効です。**B15は守護者より手前の空き床4地点を追加登録し、安全な候補が5地点になりました。調査Lv3も正式範囲のB11～B15から選択します。** 階段・宝箱・泉・毒沼・落とし穴・スイッチ・扉・石碑・ボス上には配置しません。受注前にも地点を再検証し、不足時は受注せず`QUEST SPAWN FAILED`へ種別・Lv・対象階・必要数・有効候補数を記録します。表示した対象階を受注後に勝手に変えません。

候補検証は`.venv/Scripts/python.exe tools/verify_quest_spawn.py`で実行できます。全15階の登録数・フィルタ前後の候補数・各種別の配置可否を表示し、`verification/quest_spawn.json`へ結果を出します。今回の調査・修正と、報告されたB14のWeb/SAVEケースの確認範囲は[QUEST配置調査報告](verification/QUEST_SPAWN_REVIEW.md)を参照してください。SAVEの版は1のままで、対象階・進捗・flavor_idを保持し、座標だけロード時に安全な候補から再構築します。調査1/3なら残り2地点を表示します。

## α版 Phase 3：タイトルと導入

起動すると文字だけのタイトル画面が開きます。十字キーで「はじめから／つづきから」を選び、Aで決定します。Bはタイトルでは何もしません。「はじめから」は短い暗転の後、白地に黒文字の4ページの導入ストーリーへ進みます。最後のページでAを押すと、既存の拠点TOPを約3秒だけ操作不可で表示し、初回だけ城下町の説明を表示します。説明でAを押すと、5施設を操作できる拠点TOPへ入ります。「つづきから」は保存済みデータを読み込み、導入なしで拠点TOPへ入ります。保存がない・読み込めない場合はメッセージを表示し、A/Bでタイトルへ戻ります。PCの矢印・Z/X、スマートフォンの仮想十字キー・A/Bで操作できます。

導入文は[data/intro.json](data/intro.json)の`pages`、初回のみ表示する城下町の説明は同じファイルの`hub_intro`を編集します。行やページの変更はゲーム再起動後に反映され、文章は自動で中央に配置されます。拠点プレビューの長さは`rpg/opening.py`の`HUB_PREVIEW_FRAMES`（30FPSで90フレーム）で変更できます。プレビュー中は操作できず、帰還時にはプレビュー・説明とも再表示されません。タイトル文字を将来Pyxel Editorの画像に替える場合は`rpg/dungeon_app.py`の`draw_title_logo()`を変更します。タイトルメニューとNEW GAME・CONTINUEの処理は別の関数です。NEW GAMEはパーティ・技・道具・宝・調査・ダンジョン進行を初期化します。AUDIO PASS 01以降はタイトルに専用曲、導入に拠点曲を再生します。

## α版 Phase 2：通常戦闘への突入演出

探索中の通常遭遇では、現在の探索画面を3フレーム（約0.1秒）静止表示してから、160×120の中央で4分割します。左上・右上・左下・右下へ各片を毎フレーム5ピクセルずつ動かし、奥には既存の戦闘画面を描画します。4分割は18フレーム（約0.6秒）、静止を含め計約0.7秒でコマンド入力を始めます。演出中の操作は無効で、終了時に押しっぱなしだったキーやタッチボタンは一度離してから押し直す必要があります。ボス戦には適用しません。DEBUG MODE（F9）中は探索画面で**T**を押すと通常戦闘の演出を繰り返し試せます。

拠点TOP（BASE / TOWN HUB）とGUILD・TRAINING・PUB・SHOPの施設TOPでは、確定通貨をヘッダー右上に`TRZ 3`の形式で表示します。`DungeonApp.draw_banked_trz()`を共用し、右端156・Y=2、最大64pxの枠内で右揃えします。拠点TOPの画像下にはTRZを重複表示しません。メニューは`rpg/hub.py`の`HUB_MENU_Y=43`、`HUB_MENU_STEP=17`を共用し、SAVEを含む4項目でもフッターに重なりません。

## 最終システム検証版（2026-09-27）

戦闘の基本コマンドは **SKILL / ITEM / GUARD / RUN** です。GUARD（まもる）は1人の1行動を使い、そのターンに受けるダメージを50%にします。技・道具・宝は消費せず、攻撃や回復、成長・閃きの加点もありません。通常攻撃はなく、技は有限回数です。戦闘不能（HP 0）は戦闘後も探索中も続き、4人全員が戦闘不能になると全滅です。拠点へ戻ると全員回復します。

- **REVIVE** はRAREの回復技。戦闘不能の味方を最大HPの25%（最低1）で蘇生します。3回で消滅し、使い切るとMASTEREDとして記録されます。攻撃技のPOWER倍率は付きません。蘇生割合は`data/items.json`、技の使用回数は`data/skills.json`で調整できます。
- **POTION / PHOENIX ASH / REMEDY** は各9個まで。POTIONは生存者のHPを30回復、PHOENIX ASHはREVIVEと同じ蘇生です。REMEDYは生存者の毒・マヒ・睡眠・混乱をすべて治療し、BUFF/DEBUFFは解除しません。探索中も毒の治療に使用できます。治す状態異常がない対象・戦闘不能の対象には消費しません。戦闘中の道具使用はそのキャラクターの1行動を消費します。満杯の宝箱は中身を保持して開かず、探索の進行は可能です。
- **SHOP** は確定した宝でPOTION（1）、PHOENIX ASH（4）、REMEDY（2）を購入します。価格と初期所持数は`data/items.json`で編集します。未確定の宝は使えません。
- **回復の泉** は生存者のHPを全回復し、同じ探索では各泉1回だけ使えます。戦闘不能者・技回数・道具は回復しません。配置はPyxel EditorのTilemapにある泉タイルで編集します。
- **RUN** は通常戦闘から探索へ逃げる非常手段です。失敗すると敵の行動を受け、成功時は能力成長・閃き・報酬なしです。HP、技回数、アイテムの消耗は保持します。ボス戦では使えません。基本15%、AGI差補正は最大±15%、最終成功率は10～30%。設定は`data/items.json`です。拠点へ帰るRETURNとは別です。
- 拠点の **PUB** では確定した宝1個で噂を聞けます。攻略情報70%と雰囲気情報30%で、直前の噂は連続しません。文面は`data/pub_messages.json`で編集します。
- 戦闘中の技カテゴリ使用は既存の成長判定に軽い補正を加えます。物理はSTR/HP、速攻はAGI/STR、魔法はINT/AGI、補助はAGI/INT、回復はINT/HPです。同カテゴリは3回で補正上限に達します。数値は`data/settings.json`の`category_growth`、最終上限は`growth_bonus_cap`で調整します。F9でDEBUGを有効化し、戦闘中F3で使用回数・補正・逃走率を確認できます。F6/F8で次の逃走成功/失敗を固定できます。拠点/探索中F1には戦闘不能、灰、薬満杯、泉、酒場、確定宝の検証項目があります。

起動は`run.cmd`、または下記のローカル起動手順です。編集後のWeb版は`tools/build_web.cmd`で`dist/game.html`を更新します。PC Python・ブラウザともGUILDから保存できます。

### 音声停止からの復帰

スマートフォンの画面ロックやタブ切り替えで音声が止まっても、戦闘結果は進められます。勝利演出は2.4秒または72更新フレームで解除し、音声チャンネルの終了を待ちません。Web版では復帰後の最初のタップ・キー入力で音声再開を試みます。再開に失敗しても無音のまま遊べます。DEBUG中の戦闘F3にはWeb Audioの状態を表示し、非表示・復帰の記録はブラウザの開発者コンソールで確認できます。音声停止の模擬検証は`python tools/verify_audio_recovery.py`です。

この検証スクリプトは、無音時のMASTERED・閃き・入れ替えと、即勝利から結果表示・探索復帰までの100回連続遷移を確認します。成長タイプと技カテゴリの補正は`data/settings.json`、MASTERED攻撃倍率は`rpg/models.py`の`MASTERED_POWER_MULTIPLIER`で調整できます。成長補正は今回強化していません。

## 外部プレイテスト反映（2026-09-23）

有限回数の技・閃き・6枠の取捨選択・深度倍率・15階と3ボスはそのままに、探索と習熟に以下を追加しました。起動は従来どおり`run.cmd`。Web配布用は`dist/index.html`と更新済み`dist/game.html`です。

### 宝箱・地形

- **通常宝箱**：宝+1/+2/+3、薬、閃き抽選、罠、空の箱を重み付き抽選します。罠5%・空3%は維持し、HP回復報酬はありません。開封結果はA（PCではZキー）で読み進めます。
- **レア宝箱**：Image Bank 1の(72,0)に描いた薬の絵で表示します。配置はPyxel EditorのTilemapで変更できます。報酬は宝+3が40%、宝+5が30%、閃きが30%。通常箱の閃き報酬は60%で成功、レア箱の閃き報酬は100%で成功し、全レア度から抽選します。LEGENDも対象です。満杯なら入れ替え画面で選びます。
- **毒沼**：入るたび生存者全員HP−2。HP1で止まり、戦闘不能者は復活しません。その場でAを押しても再ダメージはありません。
- **落とし穴**：同じ階の入口/上り階段の位置へ戻ります。下の階へ落ちず、ボスロックを飛び越えません。移動先の階段は自動発火しません。
- **回復の泉**：1回の探索につき各泉1回、全生存者HPを最大まで回復。復活はしません。拠点から再出発すると再使用できます。

宝箱の開封状態・泉の使用状態は探索中だけ保持します。薬が満杯なら箱を開けず中身を保持し、再抽選を防ぎます。宝は未確定として加算され、徒歩/RETURNで帰還して確定します。地形上の専用タイルはEditorで移動でき、ゲーム起動時に座標を上書きしません。

### MASTEREDボーナス

最後の1回を実際に使い切ると「MASTERED!」と専用SEが出ます。**次に取得した攻撃技の最終ダメージが1.2倍**になります。例えばMETEORの使用回数は再取得後も3/3で、威力だけが上がります。倍率は累積せず、現在所持中の技には後から適用されません。MASTERED記録はパーティ共通です。

拠点の有料再習得は従来の少量在庫を維持します。MASTERED後も回数は変わらず、攻撃技なら再取得版に威力1.2倍を適用します。回復・バフ・デバフ・RETURNはMASTERED記録のみです。入れ替えで捨てるだけでは習熟しません。SKILL ARCHIVEにも再取得時の効果を表示します。SAVEした記録はCONTINUEで復元できます。未保存の進行は終了すると失われます。

### QUEST BOARD

拠点TOPの「PUB」→「QUEST」でLvを選び、Z/パッドAで探索・調査・討伐を選択します。依頼文と依頼人・対象階・報酬を確認してから「受注する／受注しない」を選びます。上下で選択、Aで決定、Bで一つ前へ戻ります。Lv1は初期解放、Lv2はB5Fボス、Lv3はB10Fボス撃破で解放されます。同時受注は1件です。受注中の画面には種別・Lv・対象階・進捗・報酬・帰還待ち状態を表示します。達成して安全帰還すると受注を解除し、同種・同Lvを含めて次の依頼を受けられます。

| 全3種共通のLv | 対象階 | 解放条件 | 探索 / 調査 / 討伐の生還報酬 |
|---|---|---|---|
| Lv1 | B1～5F | 最初から | 2 / 3 / 4 TRZ |
| Lv2 | B6～10F | B5Fボス撃破 | 4 / 5 / 6 TRZ |
| Lv3 | B11～15F | B10Fボス撃破 | 6 / 7 / 8 TRZ |

必要数の安全な候補がある階から1階を抽選し、探索は人影1地点、調査は虫眼鏡2/3/3地点、討伐は魔物の顔1地点を重ね描画します。B15は安全な候補5地点を使い、調査Lv3を含めB11～B15すべてが対象です。対象階に入ると階番号付きのヒントを表示します。**その場ではQUESTのTRZ報酬なし**。徒歩またはRETURNで生還すると自動報告します。全滅時は進捗が0になり、同じ地点でやり直せます。討伐は既存敵1体を使った通常ルールの追加戦闘で、RUN・DRAWでは対象が残ります。宝箱とは独立した目的です。

### 補助技の準備と演出

発見済みのBASIC/COMMONに加え、**RAREの補助・弱体技**を再習得できます。現在は装甲砕き（ARMOR BREAK）と集中（FOCUS）、宝コスト4・通常再習得3回です。RARE攻撃、LEGEND、UNCOMMONは対象外。所持中の残数補充はできません。設定は`data/skills.json`の`relearn_cost`/`relearn_uses`です。

アイアンゴーレム・狂戦士・暗殺者には、補助なしで基本技の継戦、魔法、高威力物理の3通りで勝利できることを自動戦闘で確認します（育成後の固定能力条件。あらゆる低能力パーティの勝利を保証するものではありません）。装甲砕き等は効率を高める選択肢として維持しています。

宝箱の短いSEと初回MASTERED専用SE、枠付き探索メッセージを追加。新タイルも既存の緑4色（色番号0～3）で作成し、32色Editorパレットや主人公画像は変更していません。今回BGMは追加・変更していません。既存の通常戦闘曲、ファンファーレと終了待ちを維持します。SE定義は`rpg/sound.py`、Sound 62/63、再生チャンネル0です。

| 地形定義・画像の位置 | `rpg/tiles.py`、下記Editorタイル表 |

## 外部プレイテスト / Web版

公開後は `https://<GitHubユーザー名>.github.io/<リポジトリ名>/` がWeb版のURLになります。`dist/index.html`が公開用の入口で、PLAYボタンから公式Pyxel Webランタイムを用いたゲームを起動します。PC・スマートフォンのブラウザに対応し、スマートフォンは**横向き推奨**です。

### ゲーム概要

4人パーティで探索するターン制ダンジョンRPGです。通常攻撃はなく、有限回数のスキルだけで戦います。戦闘後には新しいスキルをランダムで閃き、使い切った技は消滅してMASTEREDに記録されます。SKILL ARCHIVEでは発見・習得の状況を確認できます。深い階ほど閃きやすく、宝を持ち帰ると拠点で技を立て直せます。RETURNは拠点へ安全に戻る探索用スキルです。B5F、B10F、B15Fにはボスがおり、B15Fのボスが現在の最終ボスです。

### 現在のゲームループ

ダンジョンへ入る → 戦闘でスキルを消耗する → 新しい技を閃く → 宝を拾う → 先へ進むか帰還するか決める → 宝を拠点へ持ち帰る → 技を立て直す → 再び探索する、という流れです。

**通常攻撃コマンドはありません。戦闘の選択肢はSKILL / ITEM / GUARD / RUNです。** SKILLから有限回数の技を選びます。GUARDは自分への被ダメージをそのターンだけ半減します。最小ダメージ1のルールは維持します。軽減率は`rpg/battle.py`の`GUARD_DAMAGE_MULTIPLIER`で変更できます。残数0で技が消滅し、空いた枠に新たな技を閃く循環を検証します。保持できる技は初期設定で6枠。帰還や全滅でHPは回復しますが、**スキルの残数は回復しません**。MP/SPはありません。

## 宝の持ち帰り・スキル再習得（追加仕様）

1. **UNBANKED TRZ（未確定宝）**は今回の探索で得た宝です。探索画面上部に表示します。**BANKED TRZ（確定宝）**は帰還して確保した宝で、拠点と再習得画面に表示します。両方ともゲーム終了でリセットされます。
2. B1F入口へ徒歩で戻るか、探索中にRETURNを使うと、未確定宝をすべて確定宝に加算して未確定宝を0にします。帰還結果に今回の確保数・確定宝総数を表示し、Aで拠点へ進みます。宝0個でも帰還できます。HPは全回復、技残数は持ち越します。再出発は常にB1Fです。
3. 全滅では未確定宝だけを全ロストします。確定宝・キャラクター・能力・習得技・図鑑への追加ペナルティはありません。戦闘で実際に消費した技回数は戻りません。
4. **RESTORE SKILL**は拠点TOPの「TRAINING」内です。キャラ→技→コスト確認→Aで購入します。Bで戻れます。満杯なら既存の入れ替え画面で忘れる技を選び、もう一度Aで確定します。見送り・取消は無料で、宝は入れ替え確定時にだけ消費します。捨てた技はMASTEREDになりません。攻撃手段を失わないよう、補助技の再習得時には攻撃技を1つ残してください。
5. 全員共通の図鑑で**DISCOVERED済みのBASIC・COMMON・RARE補助技**を再習得できます。UNCOMMON・RARE攻撃・LEGEND、未発見技は対象外です。既に所持する技の購入・残数補充はできません。
6. 宝コストはメモ帳で`data/skills.json`の各技の`relearn_cost`を編集します。初期設定はBASICが1個、COMMONが2個、RETURNが3個、RARE補助が4個です。確定宝のみ使用でき、不足時は取得できません。
7. 再習得時の基本回数は`relearn_uses`です。初期値は最大回数の半分（端数切上げ）、RETURNは1回、RARE補助は3回です。1～`max_uses`の範囲で設定してください。MASTEREDでも使用回数は変わりません。通常の閃きでは最大回数で取得します。
8. **RETURN**はCOMMONの探索専用補助技です。通常の閃き対象で、普通の技枠を1枠使います。探索でB→「RETURN」→生存している使用者→Aで1回消費して帰還します。これは無料帰還コマンドではなく、所持するRETURNスキルへのショートカットです。「習得技 SKILLS」でもRETURNを選んでAを押すと同じ使用者選択へ進みます（そのキャラクターを初期選択）。Bで元の画面へ戻れます。使用者一覧にUSESを表示し、未所持・Uses 0・戦闘不能は使用できません。両経路とも既存の`Session.field_return()`を1回だけ呼び、通常取得は3回、使い切ると消滅してMASTEREDに登録されます。通常戦・ボス戦・守護者連戦開始後には使用できません。成功時は同じ安全帰還処理で未確定TRZを確保し、QUESTのお礼・報酬へ進みます。
9. RETURNも`data/skills.json`の`id: "return"`で名前・説明・最大回数・再習得費用・再習得回数を変更できます。帰還効果は`effect: "return"`、対象は`self`、分類は`support`です。宝の管理は`rpg/treasure.py`、取得は`rpg/dungeon.py`、再習得と技消費は`rpg/battle.py`、帰還確定と画面は`rpg/dungeon_app.py`が担当します。
10. **DEBUG**はF9で有効化します。拠点・探索中のF2で宝メニューを開き、↑↓・Zで「未確定宝+5」「確定宝+5」「未確定宝を0」「RETURNを取得」「拠点の再習得を開く」を選べます。←→で取得キャラ、Xで閉じます。再習得への直行は拠点のみです。F10の技一覧のBで再習得対象技を発見登録、Mで習熟登録、Rで強制再取得。F1に探索・クエスト試験があります。F11のデバッグ帰還も宝を確定します。F9がOFFならこれらの操作は無効です。

まず宝を3～5個持って徒歩帰還し、確定宝で基本技やRETURNを用意して再出発してください。次は持ち帰らず進んだ場合と比べ、帰還の判断やスキル運の下振れからの立て直しを確認できます。この検証ループとは別に、PC版のSAVEはPhase 7Aで追加しています。

追加検証は`python -m unittest discover -s tests`と`python tools/verify_camp_ui.py`で実行できます。後者は実Pyxelで帰還・購入・取消・入れ替え・RETURNの消滅を操作し、文字の画面内収まりを検査します。画像は`verification/screenshots/camp_*.png`へ保存します。

## 2. 起動方法

検証環境：Windows、Python 3.14.7、Pyxel 2.9.9。Python 3.11以上を使用してください。

この作業フォルダには仮想環境を用意済みです。**`run.cmd`をダブルクリック**すると起動します。別のPCではPythonをインストールし、最初に`setup.cmd`を実行してください。

PowerShellから手動でセットアップする場合：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

`python`が見つからない場合は、最初のコマンドを`py -m venv .venv`に変更してください。Windows用`setup.cmd`は一般的なユーザー別Pythonインストール先も探します。依存ライブラリのインストール時にはネット接続が必要です。ゲーム自体はオフラインで動きます。

再現用乱数seed、最初からDEBUG MODEでの起動：

```powershell
.\run.cmd --seed 42
.\run.cmd --seed 42 --debug
.\run.cmd --battle-lab --seed 42
```

同じseed・データ・行動順・DEBUG切替なら同じ結果になります。ゲームは起動時にJSONと画像を読み込みます。編集を反映するにはゲームを再起動してください。

WindowsではゲームウィンドウのIMEを自動解除します。日本語入力ONのままZ・Xを押すと未確定文字の入力に取られ、矢印だけ動く問題への対策です。別アプリから戻った際も解除します。日本語の画面表示はそのままで、メモ帳やPyxel Editorの日本語入力設定は変更しません。処理は`rpg/keyboard.py`にあります。修正を反映するにはゲームを再起動してください。

## 3. 探索・戦闘の操作方法

起動するとタイトル画面です。「はじめから」→4ページの導入→約3秒の拠点プレビュー→初回だけの城下町説明→5施設の拠点TOPと進みます。拠点の「DUNGEON」で1F入口から出発し、「TRAINING」→「SKILL ARCHIVE」で収集状況を確認できます。探索中はD-PADで1マス移動、Bで「状態 / 習得技 / 道具」メニュー、Aで足元を調べます。階段・宝箱・ボス・入口は踏んでも作動します。階段到着時に即座に往復することはありません。

B15F以外の床で敵と遭遇します。B5F・B10Fもボス撃破前後の通常探索では遭遇します。結果と技の入れ替えを終えると**同じ階・同じ位置へ戻ります。HP・戦闘不能・技残数を持ち越します**。戦闘中の構え・一時強化・技の再使用待ちは戦闘終了時に解除します。HP成長は最大HPだけを増やし、現在HPを回復しません。

入口まで歩いて戻ると拠点で全員のHPを回復・戦闘不能も解除します。所持品・成長・技の残数・ボス撃破状態は維持します。消滅した技は戻りません。ボスタイルに入ると会話を表示し、Aで読み進めてから固定ボス1体との戦闘を始めます。Bで会話から探索に戻れます。育成結果と入れ替えの後、撃破メッセージをAで閉じて先へ進みます。

| エリア | 階層 | ボス | 撃破後 |
|---|---|---|---|
| 第1 | B1F～B5F | B5F: 迷宮の守護者 `guardian` | B6Fへの下り階段を解放 |
| 第2 | B6F～B10F | B10F: 技の番人 `skill_keeper` | B11Fへの下り階段を解放 |
| 第3 | B11F～B15F | B15F: 深淵の王 `depth_lord` | DUNGEON CLEAR |

B5F・B10Fは通常探索中にランダム遭遇があり、ボス会話・戦闘中にはありません。B15Fだけは専用最終フロアとして、守護者開始前・連戦中・泉からデーモンまで・撃破後のすべてで通常ランダム遭遇なしです。B15Fの探索・調査・討伐QUESTは引き続き有効です。未撃破のB5F・B10Fの下り階段を使うと案内が出て、その場に留まります。撃破済みボスは再出現せず、帰還・全滅・階段往復後もロック解除を保持します。状態は`Dungeon.defeated_bosses`で管理（内部の階番号は0始まり）。B15F後の進行は上記Phase 6A/6Bを参照してください。通常の周回はありません。PC版では撃破状態もSAVE/LOADの対象です。

### 探索の道具と宝箱

ポーションは初期2個・上限9個、探索メニューの「道具」で生存する味方1人のHPを30回復します。満タン・戦闘不能なら消費しません。戦闘中の道具使用はありません。

**探索中の回復技**は、Bでメニュー→「習得技」をAで開き、←→で使用者、↑↓で回復技を選んでAを押します。↑↓で対象、Aで使用、Bで技一覧へ戻ります。技の残数を1消費し、0になると消滅します。使用者が戦闘不能、対象が満タン・戦闘不能なら消費しません。探索中にはターン待ちを適用せず、成長寄与は戦闘中の使用だけを集計します。

宝箱は`data/exploration.json`の種類別テーブルで、宝・薬・閃き・罠・空を抽選します。宝箱からHPは回復しません。宝は帰還で確定し、全滅すると未確定分だけを失います。一度開いた箱は、その探索中は再取得できません。薬が上限なら箱を開けず、中身を保持します。薬を使って戻れば取得でき、調べ直して中身を再抽選することはできません。拠点から再出発すると箱・泉を再使用できます。薬・確定宝は持ち越し、初期の薬2個が再支給されることはありません。開封状態はメモリ上だけに記録し、元の`game.pyxres`を変更しません。

### 戦闘・共通操作

| キー | 操作 |
|---|---|
| D-PAD（PC矢印キー） | コマンド・技・対象・ページ選択。履歴ではスクロール |
| A（PC Zキー） | 決定、戦闘ログ送り、結果の次ページ |
| B（PC Xキー） | 対象・技選択を戻る。コマンド画面では1人分の入力を取り消す |

敵はアイコンだけを表示し、平常時の枠・名前・HPバーは表示しません。敵を選ぶとアイコン左の`>`とメッセージ欄の敵名で対象を示します。敵の現在HP・最大HPは表示しません。味方が敵の攻撃や魔法でダメージを受けると、画面全体が6フレーム揺れます。

### 残数と消滅

- 技の選択画面と習得技一覧に`現在/最大`の回数を表示します。戦闘中の`待`は再使用待ちです。
- 実際に行動した時点で1回消費します。対象選択中の取消、先に戦闘不能になった使用者、戦闘が先に終わって実行しなかった行動は消費しません。
- 七連斬の7ヒットやカウンターの複数反撃も、行動1回につき消費1です。回復・補助にも同じ規則を適用します。戦闘中は満タン対象への回復も行動が成立すれば消費します。
- 使い切った技はその行動直後に削除し、「使い切り消滅」と初回の「MASTERED!」を戦闘ログ・結果・履歴に残します。消滅した技の使用実績は、その戦闘後の成長判定まで保持します。
- 空き枠への閃き・入れ替えで得た新技は最大回数から開始します。同じ技でもキャラごとに残数を管理します。消滅・放棄・見送った技を再び閃く可能性はありますが、再取得の保証はありません。
- 拠点帰還・全滅・次戦・ポーションでは回数を補充しません。`--battle-lab`の連戦でもHPだけを回復します。残数の補充はデバッグ専用です。

**試作用の救済**：すべての直接攻撃技（`damage`/`drain`）を失ったキャラには、パンチ30回を自動付与し、ログに「救済」と記録します。MASTERED済みなら再取得版として威力1.2倍です。最後の基本技を使い切った場合も対象です。カウンターだけでは能動的に攻撃できないため救済対象になります。通常は消滅で空いた枠を使います。入れ替え等により全枠が回復・補助技だけになった場合は、末尾の技を放棄してパンチを入れます。この場合は入れ替え確認画面にも案内します。救済は進行不能防止用の暫定仕様です。

4人のコマンドを決めた後、AGIの高い順に敵味方が行動します。同AGIはランダム。GUARDとCOUNTERの構えは攻撃より先に成立します。GUARDは次ターン開始時と戦闘終了時に解除され、ボス戦でも選べます。RUNはボス戦で選べません。入力後に戦闘不能になったキャラは行動せず、選んだ敵対象が倒れた場合は生存対象へ自動変更します。POTION/HEALでは戦闘不能は治らず、REVIVE/PHOENIX ASHだけが蘇生できます。

パンチは`STR × 1.0`、速撃は`STR × 0.5 + AGI × 0.7`、火花は`INT × 1.2`。物理技は威力から敵の`defense`、魔法技は`magic_defense`を引き、ダメージは整数に丸めて最低1。AGIは行動順と一部の技に使います。敵はSTR攻撃・INT魔法を使い、技在庫管理はありません。味方の恒久的な能力はHP/STR/AGI/INTの4つのままです。

勝利すると戦闘不能者を含む4人全員に成長・閃き判定を実行し、`ロウ STR +1`や`ロウ 閃き! メテオ [伝説]`をページ表示します。結果をAで最後まで送ると、入れ替え待ちがあれば選択画面へ、なければ探索へ戻ります。

全滅時は`PARTY DEFEATED`の結果に未確定宝のロスト数を表示し、未確定宝を0にします。確定宝・薬・育成状態・技残数・図鑑を保って拠点へ戻りHPを全回復します。敗北時の成長・閃きはありません。60ターンで決着しなければDRAW（引き分け）となり、成長なしで元の探索位置へ戻ります（宝のロストなし）。**`--battle-lab`では結果の次にHPだけを全回復して次戦へ進みます。消費済みの技回数は戻りません。**

上部に今回の戦闘番号とターン番号、能力確認画面に終了した戦闘数・勝利/敗北/引き分け数を表示します。履歴のBは戦闘番号です。DEBUGを使った成長履歴にはDEBUGと記録されます。HP/STR/AGI/INTと操作キー名は半角表記です。

### SKILL ARCHIVE

拠点TOPの「TRAINING」→「SKILL ARCHIVE」を選ぶと、全技のDISCOVERED・MASTERED数、達成率、レア度別の発見/習熟/総数を表示します。数値は`data/skills.json`から毎回集計するため、技数やレア度の内訳を固定値にはしていません。Aで一覧と集計を切り替え、一覧は↑↓でスクロール、BでTRAININGへ戻ります。

- **DISCOVERED**：初期所持、閃き、救済、デバッグ取得を含め、そのIDの技を一度でも取得した時点で登録します。枠が満杯で入れ替えを見送っても登録は残ります。
- **MASTERED**：戦闘または探索回復で残り1回を実際に使い、0になって消滅した時だけ登録します。枠入れ替えでの放棄、閃きの見送り、デバッグで残数を変えただけの場合は登録しません。
- 一度登録した状態は、その起動中は維持します。MASTEREDした攻撃技は次回取得した分から最終ダメージ1.2倍。何度再取得しても累積しません。補助技は記録のみ。使用回数は変わりません。PC版では記録と所持コピーごとの強化状態もSAVE/LOADで復元します。
- 一覧のDはDISCOVERED、MはMASTEREDです。未発見技の名前は`??TRZTRZ??TRZTRZ`で隠します。順番は`data/skills.json`の記載順で固定です。選択技のTYPEはATTACK / MAGIC / HEAL / SUPPORT、未発見なら??TRZTRZと表示します。補助技も同じ発見・習熟ルールです。

状態は`rpg/battle.py`の`Session.discovered_skills`と`Session.mastered_skills`に、技名ではなく技IDの集合として保持します。技データを追加すると総数・レア度集計・一覧へ自動で反映されます。別途図鑑用の固定リストを編集する必要はありません。

### 技が6枠埋まったとき

1. 新しい技を閃いたら、結果画面に「入替待ち」と表示します。
2. 結果の最後でAを押すと入れ替え画面になります。
3. ↑↓で忘れる技を選びます。既存技の残数、新技の最大回数、レア度・威力・待ち時間を比較できます。6枠目と見送りまでスクロールできます。
4. Aで確認画面へ進み、もう一度Aで確定。Bなら選び直せます。
5. 覚えたくない場合は末尾の「新しい技を見送る」を選びます。Bでこの項目へ移動し、Aを2回押して見送れます。

複数人が同時に閃いた場合は1人ずつ選択します。放棄した技の残数を含め、結果・履歴に入れ替え内容を記録してから探索へ戻ります。成長を再抽選したり、枠上限を超えたりはしません。Dで能力・習得技を確認して戻ることもできます。

F3～F8・F10～F12はDEBUG専用です。F5～F8・F11は探索画面・拠点だけで動きます。F4での移動は通行ロックを無視しますが、通常の階段ではボス撃破を再チェックします。撃破フラグは各々独立に切り替えられます。F10は戦闘中も閲覧できますが、C/Vによる変更は戦闘外・確定済み結果画面だけで使えます。満杯なら確認付き入れ替えへ進み、見送りもできます。入れ替え中はF10を開けません。Vは現在持つ選択技だけを残り1回にし、消費するまでMASTEREDにはしません。

**階層補正の比較**：F9 → F4でB1Fを選ぶと通常15.0%（x1.00）、B15Fなら30.0%（x2.00）を確認できます。DEBUG時は95%に上書きするため、実戦で深度差を比べるときは移動後にF9で通常モードへ戻してください。B15Fの戦闘はラスボスです。レア度の相対比率は全階・DEBUGで共通です。

**補助技の試験**：F9 → F10で「装甲砕き」を選んでC、続けてVで残り1回にします。F8でボスへ移動して会話後に手動で使用し、F3で敵の装甲低下と残りターン、図鑑でMASTEREDを確認できます。

F12メニューは←→で対象キャラ、↑↓で操作、Zで実行、Xで閉じます。

| 項目 | 対象と動作 |
|---|---|
| 残り1回にする | 全員の現在保持する全技を残り1回にする |
| 最大回数に戻す | 全員の現在保持する全技だけを最大に戻す。消滅技は復活しない |
| ランダムに閃く | 選択キャラに未習得候補から1技 |
| 希少以上を閃く | 選択キャラにRARE/LEGENDから1技 |
| 伝説を閃く | 選択キャラにLEGENDから1技 |
| 技枠を満杯にする | 選択キャラの空き枠だけをランダム技で埋める。既存技の残数はそのまま |

**入れ替えの簡単な試し方**：拠点でF9 → F12 →「技枠を満杯」→「伝説を閃く」。通常と同じ確認付き入れ替え画面になり、終了後は元の画面へ戻ります。候補を全て保持していれば「閃き候補なし」と表示します。戦闘の入力・行動処理中や入れ替え待ち中にはF12で在庫を変更できません。デバッグ操作は履歴に記録します。

## 4. 成長率と閃き確率を変更する場所

**`data/settings.json`**をメモ帳などで編集します。確率は0～1で指定します。

| タイプ | HP | STR | AGI | INT |
|---|---:|---:|---:|---:|
| POWER | 65% | 55% | 30% | 12% |
| SPEED | 65% | 30% | 55% | 12% |
| MIND | 65% | 12% | 30% | 55% |

各能力を独立に判定するため、1勝で複数能力が上がることも、全く上がらないこともあります。STR/AGI/INTは当選時+1、HPは`hp_gain: [2, 4]`で+2～4です。

成長補正は技データの`growth`を実際の使用ごとに加算します。`growth_per_point: 0.04`は寄与1点あたり4ポイント、`growth_bonus_cap: 0.35`は能力ごとの加算上限35ポイントです。

```text
最終成長率 = min(100%, タイプ基本率 + min(35%, 使用した技の寄与合計 × 4%))
```

パンチのSTR寄与は2なので、1回で+8ポイント、2回で+16ポイント。速撃はAGI寄与2・STR寄与0.5。ファイアはINT寄与2、メテオはINT寄与5なので、POWER型のINT成長率はメテオ1回で12%→32%、2回で上限補正に達して47%になります。ヒールはINT寄与2・HP寄与0.5です。多段技はヒット数ではなく1行動分の寄与を加算します。

寄与の集計は戦闘ごとにリセットします。技の選択・未実行・防御・探索中の回復では加算しません。敗北・引き分けでは成長しません。消滅した技の寄与も勝利後の判定に使います。Dの能力画面では、その戦闘の基本率と蓄積した補正を確認できます。純粋なタイプ別成長と比較する場合は`growth_per_point`を0にしてください。

閃きは各キャラ・各勝利につき最大1回です。探索では`min(100%, spark_chance × 階層補正)`。階層補正は**`data/dungeon.json`の`spark_multipliers`**を先頭からB1F～B15Fの順に設定します。正の倍率15個を同値または昇順で指定します。

| 階層 | 補正（各階順） | 通常の閃き率 |
|---|---|---|
| B1F～B5F | 1.00 / 1.05 / 1.10 / 1.15 / 1.20 | 15%～18% |
| B6F～B10F | 1.30 / 1.35 / 1.40 / 1.45 / 1.50 | 19.5%～22.5% |
| B11F～B15F | 1.60 / 1.70 / 1.80 / 1.90 / 2.00 | 24%～30% |

`--battle-lab`と`--simulate`は深度を持たず1.00倍です。抽選処理は`rpg/growth.py`の`spark_probability()`、戦闘開始時の階層補正をSessionへ渡して勝利時に使います。DEBUGは`debug_spark_chance`で上書きします。

| 設定 | 初期値 | 意味 |
|---|---:|---|
| `spark_chance` | 0.15 | 通常の閃き発生率 |
| `debug_spark_chance` | 0.95 | F9有効時の発生率 |
| `rarity_weights` | 12 / 48 / 28 / 10 / 2 | BASIC / COMMON / UNCOMMON / RARE / LEGENDの相対比率 |
| `skill_slots` | 6 | 習得枠。1～8で設定可能。省略時は`rpg/skill_resources.py`の`MAX_SKILLS = 6` |
| `growth_per_point` | 0.04 | 使用した技の寄与1点あたりの補正 |
| `growth_bonus_cap` | 0.35 | 能力ごとの使用補正上限 |
| `max_rounds` | 60 | 引き分けになるターン数 |

閃きが発生したら、未習得の技が残っているレア度を重みで選び、その中から均等に1技を選びます。既に覚えた技だけを候補から除きます。能力値・成長タイプ・戦闘回数による候補制限は一切ありません。LEGENDの重みは0にできないように検証しています。

全レア度に未習得技が残っている段階では、B1FのLEGENDは1キャラ1勝あたり`0.15 × 0.02 = 0.30%`、LEGEND3技が未習得ならメテオ単体は0.10%です。B15FのLEGENDは0.60%。B1FでもRARE・LEGEND・補助技すべてが抽選対象です。あるレア度を全て保持したら、残るレア度で重みを再正規化します。枠がいっぱいなら新技を保留し、結果後に入れ替えか見送りを選びます。忘れた技・消滅した技・見送った技は将来また閃く可能性があります。

ダンジョンの敵は`data/dungeon.json`の階層別設定で強化され、勝利数では強化されません。`settings.json`の`enemy_hp_per_win: 2.0`、`enemy_power_per_win: 0.25`、`enemy_scaling_cap: 50`は旧`--battle-lab`と`--simulate`だけで使用する連戦用設定です。

## 5. 技データの追加・編集

**`edit_skills.cmd`**で`data/skills.json`がメモ帳に開きます。UTF-8で保存してください（BOMありも可）。JSONはコメントや末尾カンマを受け付けません。編集エラー時は起動時に`Data error`を表示します。

例：METEORのデータ。

```json
{
  "id": "meteor",
  "name": "メテオ",
  "rarity": "LEGEND",
  "effect": "damage",
  "target": "enemy",
  "str_scale": 0,
  "agi_scale": 0,
  "int_scale": 7.0,
  "hits": 1,
  "cooldown": 4,
  "max_uses": 3,
  "skill_type": "magic",
  "growth": {"HP": 0, "STR": 0, "AGI": 0, "INT": 5},
  "description": "INTの7倍。初戦から閃く。"
}
```

追加するには既存の1項目をコピーし、重複しない半角の`id`にします。追加した技も初戦から抽選されます。`name`と`description`、味方・敵の`name`には日本語を使用できます。UTF-8で保存してください。長い名前は実際の文字幅で計測し、画面では`~`で省略、結果と履歴では折り返します。

| 変更したい内容 | 編集場所 |
|---|---|
| スキル枠数 | `data/settings.json`の`skill_slots`。既定6、1～8 |
| 最大使用回数 | `data/skills.json`各技の`max_uses`。1～99 |
| 威力 | `str_scale`・`agi_scale`・`int_scale`・`hits`。固定威力の別フィールドは設けず、この4項目で表現 |
| 成長寄与 | 各技の`growth`内の`HP`・`STR`・`AGI`・`INT`。各0～10 |
| 寄与から確率への換算 | `settings.json`の`growth_per_point`・`growth_bonus_cap` |
| 閃き率・レア度比率 | `settings.json`の`spark_chance`・`debug_spark_chance`・`rarity_weights` |
| 初期技 | `data/party.json`各人の`initial_skills`。技IDの配列 |

`skill_type`は`physical` / `speed` / `magic` / `healing` / `support`の分類です。実際の処理は`effect`、対象は`target`、回復系かどうかは`effect: "heal"`で判定します。成長は分類や威力から推測せず、`growth`を参照します。たとえばSTR依存の七連斬にもAGI寄与を設定できます。既存効果の技ならBattle本体を書き換えず追加できます。

| 主な技 | レア度 | 最大回数 |
|---|---|---:|
| パンチ / 速撃 / 火花 | BASIC | 30 / 30 / 28 |
| 強撃 / 二段斬り / ファイア / 応急手当 | COMMON | 20 / 15 / 15 / 12 |
| 三段斬り / ドレイン / ヒール / フレア | RARE | 8 / 7 / 6 / 5 |
| 七連斬 / メテオ / 大治癒 | LEGEND | 4 / 3 / 2 |

残数とレア度は個別設定です。大治癒もINT×10の能力依存回復で、無条件の全回復ではありません。初期技には「25回以上・再使用待ち0の直接攻撃技」が必要です。救済用の`punch`は削除せず、`damage`・待ち0を維持してください。

8×8ドットの「美咲ゴシック第2」を`assets/fonts/misaki_gothic_2nd.bdf`から読み込みます。フォントはローカル同梱のためOSへのインストールやゲーム起動時のダウンロードは不要です。対応範囲は日本語のかな・JIS第一/第二水準漢字などです。絵文字や一部の異体字は対象外です。配布元は[Little Limitの美咲フォント](https://littlelimit.net/misaki.htm)、ライセンスと作者の文書は`assets/fonts/FONT_LICENSE.txt`と`misaki.txt`に収録しています。

データの`growth_type`、`rarity`、`effect`、`target`、`skill_type`、`id`は英語の識別子のままにしてください。画面ではPOWER/SPEED/MINDを力型/速型/知型、BASIC/COMMON/UNCOMMON/RARE/LEGENDを基本/通常/上位/希少/伝説と表示します。

### 効果音の編集

`rpg/sound.py`の`init_sound()`で音程・音色・音量・速度を編集できます。BASIC技と敵の物理攻撃は音番号60の短いノイズ音、それ以外の技・敵魔法は61の音程が上がる音です。実際の行動や探索回復で鳴り、コマンド選択だけでは鳴りません。防御と戦闘不能でスキップした行動は無音です。外部WAV/MP3はゲームに読み込みません。

威力の基本式は次のとおりです。固定ダメージ・習得ボーナスはありません。

```text
round((STR * str_scale + AGI * agi_scale + INT * int_scale) * hits)
```

連撃は1対象に対する合計威力として処理し、ログにHITSを表示します。途中で別の敵に飛んだり、各ヒットで最低ダメージを加算したりはしません。SEVEN SLASHは`STR × 0.55 × 7`。METEORは`INT × 7`なので、ROUの初期INT=2なら14ダメージ、INT=20なら140ダメージになります。

`cooldown: 4`なら使用後の4ターンは使用不可、5ターン目から再使用可能。MPなどの追加能力値は設けていません。入力画面のPOWERは防御などを適用する前の威力です。

| effect | target | 効果 |
|---|---|---|
| `damage` | `enemy` | 敵1体に係数どおりのダメージ |
| `heal` | `ally` | 生存する味方1人を係数どおり回復。最大HPで打ち止め |
| `drain` | `enemy` | ダメージ後、実際に減らしたHPの半分（切捨て）を自分に回復 |
| `counter` | `self` | そのターン防御し、生き残った物理被弾ごとに係数どおり反撃。魔法には反撃しない |
| `berserk` | `self` | 使用直後からSTR部分1.5倍・被ダメージ1.25倍。使用ターン終了後から3ターン継続 |

既存効果の組合せ・係数・名称・レア度・待ち時間はメモ帳だけで変更できます。反撃の倍率も係数で変更できます。BERSERKの倍率・期間や全体攻撃など、新しい処理そのものを追加する場合は`rpg/battle.py`、必要に応じて`rpg/models.py`と`rpg/content.py`を変更してください。説明文は手動編集で、処理内容には影響しません。

### 追加した補助スキル

**`data/skills.json`の末尾6項目**をメモ帳で編集します。`effect`・`duration`・`modifier`・`max_uses`が実際の処理を決めます。説明文だけを変えても効果は変わりません。

| id / 日本語名 | レア度 | 残数 | 対象・効果（すべて3ターン） |
|---|---|---:|---|
| `armor_break` 装甲砕き | RARE | 6 | 敵DEF × 0.70（30%低下） |
| `weaken` 弱体 | COMMON | 8 | 敵の物理攻撃・魔法威力 × 0.80 |
| `slow` スロウ | COMMON | 8 | 敵AGI × 0.50 |
| `power_up` 力の鼓舞 | COMMON | 8 | 味方1人のSTR × 1.40 |
| `focus` 集中 | RARE | 6 | 味方1人のINT × 1.50（回復にも有効） |
| `guard_up` 守りの力 | UNCOMMON | 8 | 味方1人の被ダメージ × 0.70 |

3ターンには使用したターンを含み、使用直後3→ターン終了2→次ターン終了1→次ターン終了で解除します。同じ効果は重複せず、再使用時に残りターンを更新。異なる効果は共存します。SLOWはそのターンの確定済み行動順を変更せず、**次ターンの行動順から**適用します。能力の元値は書き換えず、成長率にも倍率を掛けません。

全ボスに同じ倍率で有効です。勝利・全滅・引き分けのいずれでも、戦闘不能者を含め全効果を解除します。既存の防御・カウンター・バーサーク・待ち時間も解除します。補助技を最後の1回まで使うと、その場で消滅しMASTEREDに登録されますが、付与済みの効果は期限まで残ります。使用時のINT成長寄与は初期値1です。

例えば装甲砕きは`effect: "armor_break"`, `target: "enemy"`, `skill_type: "support"`, `duration: 3`, `modifier: 0.7`, `max_uses: 6`。威力係数は3つとも0、`hits: 1`です。`duration`は1～9、上昇倍率は1.01～2、低下・軽減倍率は0.1～0.99で調整できます。既存の効果IDを使う新技はJSON項目の追加だけで閃き・図鑑に入ります。

物理ダメージはおおむね`max(1, 技威力 - DEF × 装甲低下倍率)`、魔法は`max(1, 技威力 - magic_defense)`です。その後、防御0.5倍・守りの力0.7倍・バーサーク被害1.25倍を適用して丸め、最低1にします。連撃は合計威力に対して防御を1回引きます。STR強化とバーサークは別効果なので乗算されます。

## 6. Pyxel Editorで地形・マップ・キャラを編集

**`edit.cmd`をダブルクリック**するとルートの`game.pyxres`が開きます。手動では次のコマンドです。まずファイルのコピーを取ってから編集すると戻しやすくなります。

```powershell
.\.venv\Scripts\python.exe -m pyxel edit game.pyxres
.\edit.cmd 2
.\edit.cmd 3
```

引数なしの`edit.cmd`は第1エリア、`edit.cmd 2`は第2、`edit.cmd 3`は第3エリアを開きます。PyxelのグローバルTilemapは8枚なので、5階ずつ3ファイルに分けて読み込み、ゲーム内では独立した15枚として使います。左上の人型アイコンがImage Editor、隣の四角4個のアイコンがTilemap Editorです。Ctrl+Sで保存し、ゲームを再起動して反映します。

第1エリアの実際のファイル名は`game.pyxres`です。共通のマップチップはこのファイルの**Image Bank 1**で編集・保存してください。`edit.cmd 2`／`edit.cmd 3`は起動前に、そのチップ画像と32色パレットを対象エリアへコピーします。第2・第3エリアでは同じ座標のチップを選んでマップを作れます。共通チップの編集元は`game.pyxres`に統一します。直接Pyxel Editorから開く場合は、先に`python tools/sync_map_chips.py`を実行すると両エリアが同期されます。コピーで変わるのはImage Bank 1とパレットだけで、Tilemapや音声は保持します。変更前のコピーは`verification/backups/map_chips/`に残ります。

**絵の編集元は全エリア共通で`game.pyxres`です。** `area2.pyxres`・`area3.pyxres`の画像はEditorでの地形プレビュー用で、ゲームはそれらのTilemapだけを読みます。共通の絵を変更した場合、各ファイルのEditorプレビューは古い絵のままでもゲームには変更が反映されます。通常起動でファイルを再生成・上書きしません。

**Editorのパレットは32色です。** `game.pyxpal`・`area2.pyxpal`・`area3.pyxpal`に同じパレットを設定しています。色番号0～15は従来のまま、16～31にゲームボーイ風の暗緑・苔色・黄緑・淡緑を追加しました。既存の緑4色と合わせ、32色中20色が緑系です。Editorでは16列×2段に表示され、追加色は下段から選べます。開いているEditorは一度閉じ、`edit.cmd`で開き直してください。ゲームも同じパレットを読み込むため、追加色で描いた絵を表示できます。

色を調整する場合は各`.pyxpal`をメモ帳で開き、1行に6桁のRGB値（例：`0f380f`）を書きます。色番号は行順なので、既存行の並べ替えは避け、3ファイルを同じ内容にしてください。元の絵とUIは従来の4色を使用しています。

### 使用バンクとタイル対応

- Image Bank **0**：味方・敵の16×16スプライト。マップ主人公は専用の4方向画像を使用（下記参照）。
- Image Bank **1**：地形の8×8タイル。Image Bank **2**：拠点の16×16アイコンと64×64画像。
- 各ファイルのTilemap **0 / 1 / 2 / 3 / 4**：`game.pyxres`ではB1～B5、`area2.pyxres`ではB6～B10、`area3.pyxres`ではB11～B15。各Tilemapの参照IMAGEは**1**。
- 使用範囲は`data/dungeon.json`の`width`×`height`、現在24×24、設定可能範囲8～256マス。各ファイルのTilemap 5～7は未使用です。

画面には96×96ピクセル、12×12マス相当の範囲を表示します。移動するとTilemapの表示範囲がスクロールし、主人公の中心は常にマップ表示領域の中央に固定されます。マップ端でもカメラを固定するため、マップ外側は背景色になります。右側のパーティHP表示は従来どおりです。

地形はImage Bank 1の一番上の行にあります。「タイル座標」は8×8単位、「画像座標」はピクセル単位です。ゲーム側の意味の定義はすべて`rpg/tiles.py`にあります。

### 床・壁の絵を描き直す

Image Editorの`IMAGE`を**1**にし、上表の8×8領域を編集します。床の領域を描き直すと全階の床の見た目が変わります。壁も同様です。画像の変更だけでは当たり判定は変わりません。GB風を保つ場合は色0～3を使ってください。マップ描画では0も背景色として描かれます。

### 壁や通路の配置を変える

1. Tilemap Editorへ切り替え、`TILEMAP`で編集する階（0～4）を選びます。
2. 参照する`IMAGE`が**1**であることを確認します。
3. 右下のタイル画像から床または壁を選び、鉛筆ツールで左のマップのマスを塗ります。壁を床で上書きすれば通路を広げられます。
4. `data/dungeon.json`の`width`×`height`の範囲内で編集し、Ctrl+Sで保存してゲームを再起動します。

Pythonには地形配置の配列・文字列を持たせていません。起動時に`pyxel.load()`で読み込み、表示は`pyxel.bltm()`、通行判定はTilemapの`pget()`を使います。`setup.cmd`や通常起動が編集済みマップを再生成・上書きすることもありません。

### マップを広くする

1. `data/dungeon.json`の`width`と`height`を、作りたいマス数へ変更します。最大256×256です。
2. 3つのリソースのTilemap 0～4で、左上からその幅・高さまで床・壁を配置します。
3. 各階に必要な入口・階段・ボスを1個ずつ配置し、宝箱を任意に置きます。
4. 到着地点から各イベントまで通路をつなげ、Ctrl+Sで保存してゲームを再起動します。

`width`と`height`は15階共通です。設定範囲外のTilemap部分はゲームから読みません。広げた領域の初期タイルは床と同じ番号になり得るため、外周を壁で囲み、使用する全範囲をEditorで確認してください。ゲーム起動時にはイベント数と到達可能性を設定した全範囲で検査します。

### 階段・入口・宝箱・ボスを移動する

Tilemap Editorで、元のイベントタイルを床で上書きし、新しい位置に同じイベントタイルを置いて保存します。ゲームはタイルから位置を探すので、PythonやJSONに座標を書き直す必要はありません。

| B5F / gameのTilemap 4 | 上り階段・ボス・下り階段 |
| B10F / area2のTilemap 4 | 上り階段・ボス・下り階段 |
| B15F / area3のTilemap 4 | 上り階段・ボス（下り階段なし） |

下り階段からは次の階の上り階段に到着し、上り階段からは前の階の下り階段に到着します。両階の階段のXY座標をそろえる必要はありません。宝箱は各階1～3個程度を目安に自由に移動・追加できます。入手用には閉じた宝箱タイルを配置してください。

階段の重複・不足、到達できないイベント、参照IMAGEの間違いは起動時にエラーで知らせます。B1Fに上り階段、B15Fに下り階段、B1F以外に入口、B5/B10/B15以外にボスは配置しません。ボスタイルを動かしてもフラグと会話はその階のボスに対応し、撃破済み表示も新しい位置に出ます。通行ロックは下り階段の処理で判定するので、地形上ボスを迂回できても先へ進めません。

## 7. 遭遇率・敵・ボスの調整

**`data/dungeon.json`**をメモ帳で編集します。確率は0～1です。

| 設定 | 初期値 | 意味 |
|---|---:|---|
| `width` / `height` | 24 / 24 | 各階で使用するTilemap範囲。8～256マス |
| `encounter_chance` | 0.09 | B15以外の抽選対象の移動1歩あたりの遭遇率 |
| `debug_encounter_chance` | 0.45 | DEBUG時の遭遇率 |
| `safe_steps` | 2 | 出発・階段移動・戦闘復帰後の安全歩数。DEBUGでは無視 |
| `items.initial_potions` | 2 | ゲーム開始時の薬の数 |
| `items.max_potions` | 9 | 所持上限 |
| `items.potion_heal` | 30 | 1個の回復量 |
| 宝箱テーブル | 別ファイル | `data/exploration.json`の`CHEST_REWARD_TABLE`を編集 |

床を実際に1マス移動したときだけ抽選します。壁への入力、メニュー操作、Zの連打、階段・入口・宝箱・ボスへの進入ではランダム遭遇しません。B5/B10は通常探索で抽選し、B15には通常ランダム戦闘がありません。9%は抽選対象の歩数で平均約11歩、戦闘後の安全2歩を加えると約13歩です。

`floors`配列の先頭からB1F～B15Fに対応します。通常階の`enemy_ids`が敵候補、`weights`が同じ順の出現重み、`count: [最小, 最大]`が敵数（1～4）、`hp_scale`がHP倍率、`power_scale`がSTR・INT倍率です。AGI・DEF・魔法DEFは敵データのままです。従来2～3体の階は2～4体へ変更し、1～2体の階は維持しています。B6以降に補助技が有効な敵、B11以降にその強化編成が登場します。

B5/B10の設定はボス情報のみのため、通常戦ではそれぞれB4/B9の敵候補・重み・編成数・倍率をそのまま再利用します。討伐QUESTと同じ参照方式で、敵データや遭遇率は変更しません。修正・検証結果は[ボス階の通常遭遇修正報告](verification/BOSS_ENCOUNTER_REVIEW.md)を参照してください。

敵の素の能力・名前は**`data/enemies.json`**にあります。既存項目を複製し、重複しない`id`と名前・能力を設定してから、出したい階の`enemy_ids`と`weights`へ追加してください。通常敵は`boss`を省略するか`false`にします。Pyxel Editorは外見とマップ、JSONは数値と出現候補を担当します。

### 敵・ボス能力とメッセージ

**`data/enemies.json`**の`max_hp`がHP、`str`が物理ATK、`defense`が物理DEF、`magic_defense`が魔法DEF、`agi`が行動速度、`int`が魔法威力です。`actions`がある敵はその行動weightを使用し、未設定／空なら`magic_chance`で従来の物理・魔法を選びます。`feature`は特徴メモで、特殊処理を実行するスクリプトではありません。

### 敵行動の編集（Enemy Action System Phase 1）

行動名・効果は**`data/enemy_actions.json`**、敵ごとの行動比率は**`data/enemies.json`**をメモ帳で編集します。例えば`"actions": [{"id":"attack","weight":65},{"id":"heavy_attack","weight":35}]`なら通常攻撃と強攻撃を65:35で抽選します。weightは正の相対値です。行動を外す場合はその項目を削除し、全行動を外す場合は`actions`を省略するか`[]`にします。階層による固定の特殊行動率はありません。

| action ID | 初期効果 |
|---|---|
| attack / magic | 従来の単体物理 / 単体魔法、威力1.00倍 |
| heavy_attack | 単体物理1.35倍 |
| double_attack | 同じ対象へ0.60倍×2回。KOで残りhit終了 |
| area_attack / area_magic | 生存者全員へ物理0.55倍 / 魔法0.50倍 |
| guard | 被ダメージ0.50倍。次の自身の行動開始で解除 |
| power_up | 自身の物理攻撃1.20倍、3ターン |
| weaken | 味方1人の攻撃ダメージ0.85倍、3ターン。回復量は維持 |
| armor_break | 味方1人の物理被ダメージを1÷0.85倍、3ターン |
| slow | 味方1人の行動速度0.80倍、3ターン |

味方にはDEF値がないため、敵の防御崩しは物理被ダメージ倍率で表現します。既存の敵へのARMOR BREAKは従来のDEF低下を維持します。一時効果は既存の`effects`を使用し、同じ効果は累積せず上書き・期限更新します。3ターンには付与したラウンドを含み、各ラウンド終了で残り時間を減らします。slowは作成済みの行動順を変更せず次ラウンドから反映します。

通常敵は18種類です。既存11体の初期weightは維持し、追加7体へ状態異常やpower_up／DEBUFF／area_magicを割り当てています。ボス7体はactions未設定のままで従来の行動を維持します。HUNTは元敵のactionsを引き継ぎ、従来の能力補正を使用します。

特殊行動は既存の16×16エフェクトを使用し、連撃は実際に行ったhit数だけ反復します。音声終了は待ちません。行動中の状態はSAVEに含めず、SAVE_VERSIONは1のままです。編集後のWeb反映は`tools/build_web.cmd`。検証結果は[Enemy Action Phase 1確認報告](verification/ENEMY_ACTIONS_PHASE1_REVIEW.md)を参照してください。

| 敵ID | HP / ATK / DEF / AGI / INT | 特徴と複数の対策 |
|---|---|---|
| `iron_golem` 鉄のゴーレム | 72 / 10 / 16 / 4 / 2 | 装甲砕き、高威力物理、魔法、持久戦 |

## 8. 検証方法

まず`run.cmd`で拠点から出発し、B5F→B10F→B15Fを目指してください。数値は試作用です。今回の10シード自動探索では帰還・全滅を含め99～185戦、3～6回の出発で全15階をクリアしました。短時間で補助技を比較するならF4/F8/F10、育成だけを20～50戦で比較するなら連戦モードを使ってください。

従来の育成だけを20～50戦で比較する場合は`run.cmd --battle-lab`を使います。

手動ではAの自動ターンとログ高速送りを併用すると短時間で試せます。意外な技を覚えたら手動で使い、D → Zで技の威力、D → Z → Zで成長履歴を確認してください。POWER型を2人入れてあるので、同タイプでも成長・習得技が分かれるか比較できます。

画面なしの再現可能なシミュレーションも、ゲームと同じBattle/Sessionを使用します。

```powershell
.\.venv\Scripts\python.exe main.py --simulate 20 --seed 7 --debug
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools\verify_ui.py
.\.venv\Scripts\python.exe tools\verify_media.py
.\.venv\Scripts\python.exe tools\verify_dungeon_ui.py
.\.venv\Scripts\python.exe tools\verify_resource_ui.py
.\.venv\Scripts\python.exe tools\verify_archive_ui.py
.\.venv\Scripts\python.exe tools\verify_depth_ui.py
.\.venv\Scripts\python.exe tools\verify_map_scroll.py
.\.venv\Scripts\python.exe tools\verify_expedition.py
.\.venv\Scripts\python.exe tools\balance_report.py
```

`--simulate`はHP回復付き・技残数持ち越しの連戦で、能力・習得技・残数・全履歴をJSONで標準出力します。`verify_expedition.py`は実際のTilemapを歩いて薬・帰還・全滅を含めた15階探索を検証し、`verification/expeditions.json`に記録します。どちらも満杯なら新しい技を見送ります。戦闘の自動選択は、HP半分未満の味方がいれば回復、そうでなければ使用可能な攻撃技のうち威力が最大のものを使い、全技が再使用待ちなら防御します。**補助技の戦術使用は自動選択せず、手動で試します。** 希少技の温存や育成方針を判断するAIではありません。

「弱い魔法をあえて使ってINTを伸ばす」といった育成方針は手動で試してください。シミュレーションの結果だけで面白さの判定はできません。DEBUGは短時間で習得UIを試す機能なので、通常確率での20～50戦とも比較してください。

実装後のセルフレビューと具体的な検証結果は`verification/REVIEW.md`に記録しています。

Enemy Roster Expansionで、この基盤を利用する4つの敵行動を`enemy_actions.json`へ追加しました。既存11体のweightとPLAYER Skillは維持しています。定義例は次のとおりです。

### 探索中の毒持ち越し（Status Ailment Phase 1.5）

## PLAYER Skill拡張基盤

正式Skillは31種類（BASIC 3 / COMMON 10 / UNCOMMON 5 / RARE 10 / LEGEND 3）のままです。既存の技データ・Uses・成長・閃き・素材・SAVE_VERSION 1は維持しています。今回追加した機能は、次のSkill追加工程で使う基盤です。

`target`には`enemy`、`ally`、`self`、`all_enemies`、`all_allies`、`random_enemy`を指定できます。全体・ランダム対象は個別対象選択を省略します。全体技のUses・Cooldown・成長加算は1使用分だけで、対象ごとに防御・軽減・バリアを計算します。PLAYER多段は従来どおり合算Powerによる1回のダメージ処理です。ランダム対象は発動時のBattle RNGで選び、演出側では乱数を使いません。

状態異常情報は`status_id`と`status_chance`です。IDは`data/statuses.json`の`poison` / `paralyze` / `sleep` / `confusion`、確率は敵Actionと同じ0～100の百分率（35なら35%）。`effect: "status"`でダメージなしの付与、`effect: "damage"`や`"drain"`との組み合わせでダメージ後の生存対象へ付与できます。耐性・無効化・排他・持続更新は既存の共通処理を使います。

治療は`effect: "cure"`と、解除するID配列`cure_statuses`で指定します。例えば`["poison", "paralyze", "sleep", "confusion"]`です。HPやBUFF/DEBUFFは変えません。共通APIの`cure_statuses()`は解除したIDのtupleを返し、戦闘は`last_skill_cured_count`、探索は`FieldSkillResult.cured_count`でも解除数を確認できます。

探索使用は`field_usable: true`で指定します。省略した既存データはheal/returnのみTrue、その他Falseとして互換処理します。新しいcureを探索でも使う場合は明示してください。`Session.field_use()`はheal/cure/returnを扱い、結果に`used`、`messages`、`cured_count`、`returned`を返します。探索使用ではBattle成長・Cooldownを加算しません。探索で回復/治療対象がなければ消費しません。正式CURE追加後は、戦闘でも治療対象なしの場合Uses・Cooldown・成長ポイントを消費しません。実行時の失敗としてメッセージを出し、その行動の順番は終了します。

RESTORE可否は`relearn_cost`と`relearn_uses`の明示データで決まります。両方0/省略なら不可、両方正数なら可です。片側だけ指定、負数、再取得Usesがmax Usesを超える定義は拒否します。拡張前の15技の可否・価格・再取得Usesは完全一致しています。新しいRARE Cure等は、この2項目を付けてRESTORE対象にできます。MASTERED条件は使い切りのまま、damage/drainの再取得コピーだけ1.2倍、status/cureは記録のみです。

この基盤Phase時点では正式技31種類でした。次のRoster Expansionで正式CURE・全体技等を追加しています。基盤のテスト用Skillはtests/検証時のメモリ内だけに作り、Archive/Sparkと配布データへ混入させません。[基盤45項目と必須95ケースの検証報告](verification/PLAYER_SKILL_FOUNDATION_REVIEW.md)を参照してください。
